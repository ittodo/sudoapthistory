# Native projection CI

`npm run test:daily` builds the existing Rust daily/rental implementation and runs
frozen reference cases, then the existing browser model/client tests. It does not
invoke Python. Rust 1.92.0 and Node 22.18+ are the tested toolchain.
`npm run build:daily` now accepts the native `daily-build` JSON request on stdin
(`site`, `database`, optional `missing`/`cache_dir`). Scheduled production builds use
the existing operating Rust release executable and its publication guards.

`vendor/` is a generated source snapshot from `15_26/rust/src`, not a second
implementation. `provenance.json` records the canonical commit and SHA-256 of each
source and exported file. Six modules are copied byte for byte. The guard module
contains its unchanged prefix before the collector entry points; collectors are
not part of this test executable. Production DBs, credentials, collection and
publication are not used by the suite. Rust child processes have an empty PATH.

Deployment CI tests this pinned snapshot. It does not load the adjacent operating
repository or prove that the snapshot matches its latest source. The optional
`NODO_NATIVE_SOURCE` check requires an exact match with the recorded source hashes.
Keep source synchronization separate from a release when its operating changes
do not affect this frozen test package.

To update after a canonical implementation change, run
`node tools/sync-native-projection.mjs <15_26/rust>`, then
`npm run test:daily`, whose Rust build requires `--locked`. The independently
named CI package keeps its pinned lockfile; the export checks that each registry
dependency is an exact version/checksum subset of the operating lockfile.
Review the source hashes and generated diff. The operating repository's
`node tests/run_projection_native.mjs` also checks that the exported source and
the operating executable match the canonical source. CI always checks exported
file hashes. A source update does not automatically replace expected outputs.

## Frozen references

`fixtures/` contains synthetic SQL inputs, original input bytes, expected data
hashes and manifest fields captured on 2026-09-22. No operating DB data is included.
The 10 original Python/Rust differential tests and three prior daily CI tests
passed before capturing 54 export scenarios. `fixtures/manifest.json` records
the reference source hashes. SQL fixtures retain empty months, invalid dates,
exact areas, ties, cancellations, missing trades, numeric extremes, conversion
rates, historical corrections and monthly-ledger revisions.

The regular runner compares every decoded data file byte for byte using SHA-256,
checks non-compressed assets, file sets, manifest fields, source checksums and
independently calculated versions. Compressed bytes can vary with zlib/platform;
the decoded-byte expectation is never relaxed. Warm and cross-stage reuse must
preserve generated bytes. Source DBs must remain unchanged. Corrupt caches,
maintenance gates, bad property types/rates and mid-build source drift must fail
or recover as appropriate.

Regenerate expectations only after independently reviewing a behavior change;
never replace failing expectations with the current Rust output automatically.
The old Python reference commands have been removed. The frozen cases retain
their original expected outputs and do not require Python.
