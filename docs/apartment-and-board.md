> 현재 운영·공개 자료 계약은 문서 목록의 기준 문서를 따릅니다. 날짜·건수·성능 수치는 해당 검증 조건의 기록입니다.


## 구현

- 모든 공개 페이지에서 공통 메뉴와 라이트·다크·시스템 테마를 사용한다.
- 검색·비교·실거래·지도·단지정보에서 아파트 선택 시 `/apartment/`로 이동한다. 전월세는 확인된 실제 거래키와 공개 단지 색인으로 연결한다. 기존 aptSeq와 실제 연립·다세대 `trh_…` 키를 구분하며 가짜 aptSeq를 만들지 않는다.
- 상세는 개요, 실거래, 전월세, 투자분석, 단지정보, 위치, 의견 7개 탭이다. 평형과 탭을 URL에 저장한다.
- 최신 유효 거래와 최근 평균가의 기간·건수를 각각 표시한다. 해제·원천에서 사라진 거래는 통계에서 제외하되 내역에서 확인할 수 있다.
- 단지 전체 세대수와 선택 평형 세대수를 구분한다. 여러 원천이 연결된 단지의 미확인 주차·용적률·평형 세대수는 임의 합산하지 않는다.
- 기존 `apt_<row id>` 의견을 그대로 조회한다. 여러 원천 평형이 연결된 경우 의견 원천을 선택한다.
- `/board/`에서 제목·내용 검색, 글 작성·수정·삭제, 댓글을 제공한다. 운영자는 공지 고정과 글 숨김·복구를 할 수 있다.
- 읽기는 공개, 쓰기는 기존 로그인·닉네임·CSRF·속도 제한·탈퇴 처리 정책을 따른다. 글 제목은 기존 댓글 본문의 첫 줄에 저장해 탈퇴 시 기존 삭제 정책을 적용한다.

### 공통 상세 선택 상태

검토한 공개 그룹은 기존 대표 ID 하나로 연다. 옛 공개 ID와 원천 키 URL도 같은 상세로 연결한다.
원래 단지·시공사·분양/임대 구분은 `displayGroup.members`에 보존한다.
상단 **단지 내 구분**에서 구성원을 선택하면 해당 원천의 매매 요약·거래·전월세·의견을 조회한다.
선택은 URL의 `member`에 저장한다. 원래 단지별 가격 요약은 상세 BIN에 포함되므로
선택을 바꿀 때 전국 목록이나 다른 단지 상세를 다시 받지 않는다.
통합 전체의 평형 세대수는 검토한 건물 범위의 중복 없는 집계를 쓴다.
구성원을 따로 선택하면 미확정 세대수를 임의로 나누지 않는다.
현재 대장 용도와 과거 거래 원문 분류가 다른 구성원은 두 분류와 시점을 함께 표시한다.
현재 용도로 과거 거래 당시 용도를 단정하지 않는다.

데스크톱 상세 패널이 선택 상태를 관리한다. `NodoApartmentLinks.selection()`은 열린
단지의 `id`·`row`를 반환하고, 패널이 닫혀 있으면 `null`을 반환한다. 단지가 바뀌거나
패널을 닫으면 `nodo:detail-selection` 이벤트를 보낸다. 지도는 현재 선택을 읽어
경계와 가격 라벨을 강조한다. 지도 데이터가 늦게 도착해도 같은 선택을 사용한다.
상세의 출처·iframe·키를 확인한 뒤에만 내부 이동 메시지를 반영한다.
지도 복귀와 중첩 경계 표시는 [공통 지도 선택 규칙](map-explorer.md#단지-선택과-지도-복귀)을 따른다.

## 자료와 호환 URL

### 공통 거래를 사용하는 단지 상세

2026-10-20 사용자 결정에 따라 별도로 만든 동별 전체 거래 복제본을 제거했다.
상세 화면은 기존 공통 분기 거래를 읽는다. 단지 상세 화면 자체는 유지한다.

- 매매의 거래일·가격·면적·층은 공통 거래에서 읽는다. 기존 지역·연도별
  `data/sale-details/` 파일은 거래 식별자·표시 순서·해제일을 연결하는 참조다.
  공통 거래에서 제외된 소멸 기록은 기존 예외 파일과 판정을 유지한다.
- 검토한 통합 구성원에 기존 검색 행이 없는 평형은 공통 거래의 원천 키와
  표시 면적으로 조회한다. `sharedFacts:true` 행은 기존 행 번호와 댓글 번호를 만들지 않는다.
  정확 면적·층 미상·중복·해제·소멸 표시는 공통 거래 값을 유지한다.
  해제일이 없는 자료는 미확인으로 표시한다. 기존 행의 댓글과 해제일 참조는 유지한다.
  보완 거래를 참조할 때만 daily manifest와 참조 파일의 해시 결합을 추가로 검사한다. 기존 DTO에 보완 참조가 없으면 daily 파일을 별도 입력으로 요구하지 않는다.
  보완 조회는 `housing-sale-direct.mjs`에 둔다. 상세 포장기가 읽는
  `housing-sale-detail.mjs`와 분리해 보완 조회 수정으로 상세 포장 캐시를 무효화하지 않는다.
  같은 함수를 쓰는 통합 단지 보완 생성기의 캐시 지문에는 계속 포함한다.
- 전월세도 공통 거래에서 읽는다. `data/contracts/apartment-rent/<지역>/archive-details.bin`은
  거래 참조·계약기간·계약 구분·해제일·종전 금액·갱신권만 담는다.
  거래일·면적·층·현재 보증금·월세를 다시 저장하지 않는다.
  이 기존 경로에는 연결이 확인된 아파트와 연립·다세대의 추가 정보가 함께 들어간다.
  파일 경로로 거래 유형을 판단하지 않는다.
- 실제 거래 유형은 공통 지역 메타데이터의 `property_type`을 따른다. 연립·다세대
  매매·임대 내역에는 해당 유형을 표시한다. 대장상 아파트라는 이유로 거래 원문의
  유형을 아파트로 바꾸지 않는다.
- 월별 계약 목록은 `apartment-rent`와 `rowhouse-rent`를 각각의 경로와 캐시 키로
  구분한다. 공통 거래에 연결된 행은 참조 BIN과 표시 사전으로 복원한다. 그 밖의
  계약은 unmatched BIN에 원문 필드를 보존한다. 오피스텔 계약은 지역별 묶음 JSON으로 읽는다. 계약 index의 각 월 항목은
  `bundle`(`<service>/<lawd>/recent.json` 또는 `<service>/<lawd>/<연도>.json`)을 가진다. 화면은 묶음을
  한 번 받아 월별 행(`months[YYYYMM]`)을 쓰고, 건수가 index와 다르면 그 월을 실패로 표시한다.
  월 JSON은 구 화면 호환을 위해 승인된 폐기 전까지 함께 공개한다([저장 계약](../../15_26/docs/housing-packed-storage.md#오피스텔-계약-묶음)).
- 수집 범위는 `contractArchive.sourceServices`로 실제 임대 서비스를 찾는다.
  아파트는 `coverageRef`, 연립·다세대는 `coverageServices['rowhouse-rent']`를 읽는다.
  여러 서비스가 연결된 단지는 필요한 서비스 모두 수집된 달만 완료로 표시한다.
  아파트 수집 이력으로 연립·다세대의 미수집 기간을 채우지 않는다.
- 단지 진입 색인은 단지 정보 경로와 실제 원천 지역을 안내한다.
  원천 ID 앞자리로 지역을 추정하지 않는다. 거래 본문은 포함하지 않는다.
  파일 구성과 캐시는 아래의 단지 정보 계약을 따른다.
- 상세 조회는 필요한 지역의 번호표만 읽는다. 다른 지역의 승인 대표가 필요하면
  그 지역까지 포함한다. 매매 연도와 공통 분기는 제한된 동시 요청으로 읽는다.
- 계약 추가 정보 생성은 읽기 전용 원본 DB와 공통 거래의 식별자를 연결한다.
  비공개 캐시는 지역·월 단위다. 아파트 계약만 있는 지역은 DB 변경 묶음에 포함된 월의 원문을 다시 읽는다.
  기존 서비스·수집 지역·월 인덱스로 조회한다. 기존 원천의 수집 지역과 변경 묶음의
  수집 지역을 함께 사용하므로 새 수집 지역에 들어온 기록도 포함한다.
  공통 분기 파일만 바뀌면 월별 거래 값을 비교한다. 아파트 계약만 있는 지역에서 값이 같은 월은 원문 조회 없이 재사용한다.
  연립 계약이 포함된 지역은 기존 변경 묶음에서 연립 변경이 빠질 수 있다.
  이 지역은 같은 읽기 트랜잭션에서 전체 계약 원천을 읽고 월별 실제 해시를 지역·월 키에 결합한다.
  이 실행 안에서 계산한 기준 해시는 월 키에 재사용한다. 포장 직전 원천과 공통 거래의 별도 대조는 유지한다.
  공개 파일은 월별 결과를 합친 기존 지역별 `archive-details.bin`을 유지한다.
  최초 캐시 구축과 지역의 원천 구성 변경 때는 원천별 전체 기간을 한 번 읽는다.
  변경 묶음이 불완전해 기준을 다시 만들 때는 현재 원문 해시도 키에 포함한다.
  같은 소비 번호로 재시도해도 이전 계약 추가 정보를 그대로 재사용하지 않는다.
  월 삭제·중복·정확 금액·실제 임대 서비스와 기존 번호표 검사를 유지한다.
  새 소비 위치는 외부 후보 검증이 성공한 뒤 확정한다. 월 캐시 저장만으로 확정하지 않는다.
  생성 결과의 `monthsBuilt`, `monthsReused`, `decodedMonths`, `sourceQueries`,
  `sourceRowsRead`, `sourcePayloadsParsed`로 재생성과 원문 조회 범위를 확인한다.

계약 생성 계측은 `native-build.json`의 `regional.result.generation.packing.archive`에 남는다.
`seconds`는 전체 계약 생성 시간이다. `regionMetrics`는 지역별 시간·조회 방식·생성 또는 재사용 결과와 누적값의 차이를 담는다.
`sourceMode`는 연립 포함 전체 조회(`full-rowhouse-snapshot`), 최초 기준 조회(`first-baseline`), 변경 월 조회(`batch-months`)를 구분한다.
`rawHashCalls`와 `rawHashRows`는 원천 해시 계산 횟수와 계산에 투입한 행 수다. DB 조회 행 수와 구분한다.
`timings`는 조회와 JSON 해석(`sourceReadAndParse`), 원천 해시(`rawHash`), 공통 거래 읽기·해시(`factRead`, `factHash`), 지역 캐시 읽기·저장, 월 캐시 읽기·생성·저장, 상세 포장, 월 디코딩, 지역 인코딩, 파일 쓰기를 구분한다.
시간은 초 단위이며 중첩 구간은 합산하지 않는다. 월 캐시 시간은 내부 읽기·해시·포장을 포함한다. 지역 캐시 읽기와 지역 인코딩은 파일 쓰기를 포함할 수 있다. 공통 거래 해시는 최초 읽기를 포함할 수 있다.

공식 실행기의 `build-housing-from-native.mjs.log`에는 stderr 진행 기록을 즉시 저장한다.
`housing_build_phase`는 각 단계의 시작·완료·실패와 시간을 남긴다. 실패하면 이미 끝난 단계와 실패 단계의 시간도 남긴다.
`contract_archive_region_start`와 `contract_archive_region`은 지역 시작과 완료를 기록한다. 5초 이상 걸린 월은 `contract_archive_slow_month`로 기록한다.
`contract_archive_failed`는 실패 지역·월·내부 단계와 그때까지의 계측값을 남긴다. 원문 payload는 기록하지 않는다.
원천 또는 공통 거래 해시 불일치 오류에는 지역·월과 예상·실제 해시를 표시한다. 이 계측은 성공 판정이나 소비 확정을 대신하지 않는다.
생산 코드 변경 뒤 첫 캐시 구축 시간은 다음 실행의 재사용 시간과 구분한다.

동별 복제본 2,236개와 그 전용 수집 정보 1개를 제거했다. 과거 계약 추가 정보
7,916,761건은 지역별 78개 파일과 수집 정보 1개로 옮겼다.
공통 거래 원본·연결 승인·화면별 집계 정책은 유지한다.

계약 추가 정보 7,916,761건을 이전 복제본과 전수 대조했다. 모든 값이 일치했다.
변경 경로 시험 32개와 주택 저장·읽기 시험 56개가 통과했다.
브라우저에서는 통합 단지, 좌표 없는 단지, 이전 URL과 과거 전월세를 확인했다.

약 4.5초였다. 기존 공통 자료 조회의 같은 조건 측정은 약 18초였다.
동별 복제본을 쓰던 0.5초보다 느리며, 공통 파일을 재사용하는 선택의 비용이다.

단지 상세 전환 단계의 패키지는 19,445개 파일이었다. 동별 복제본을 넣었던 미배포 패키지보다

이는 패키지 전체 비교값이며, 그 사이의 기업 자료 갱신도 포함한다.

지도 가격 월별 계산 1,890개와 분기 결과 636개는 재계산 전후 바이트가 같았다.

### 단지 정보와 호환 URL

현재 리뷰 계약에서 `npm run build:apartments`는 생산자가 준비한 DTO의 원천 연결을 확인하고 그대로 재사용한다. JSON을 BIN으로 자동 전환하거나 진입 색인을 다시 쓰지 않는다. `npm run build:apartments -- --verify`는 준비된 자료의 파일 해시와 상세 참조를 검증한다. 원본 DB와 연결 승인 상태는 수정하지 않는다.

운영 자료의 BIN 전환은 [공식 Rust 릴리스](../../15_26/docs/site-release-workflow.md)의 격리 후보 생성 경로가 담당한다. 후보의 최종 BIN과 이전 JSON 폐기 목록을 함께 검토한다. 직접 명령은 기존 JSON index가 있는 구 계약 작업 공간에서도 BIN 전환 쓰기를 거부한다. 기존 자료가 없는 구 계약 fixture의 생성 기능은 유지한다. 파일을 직접 삭제하거나 배포 패키지에서 숨겨 전환을 대신하지 않는다.

변경된 생성·읽기 코드는 상세 256개와 요약 256개를 `packed-records-v1` BIN으로 처리한다. gzip 해제 후의 magic은 `PGRCD001`이다. 단지 ID 색인으로 선택한 단지만 복원한다. 상세 객체 전체를 미리 만들지 않는다. 가격·면적 등 숫자는 f64로 보존한다. 물리 형식은 [공개 저장 규칙](../../15_26/docs/housing-packed-storage.md)을 따른다.

| 파일 | 역할 |
| --- | --- |
| `data/apartments/<묶음>.bin` 256개 | 단지 기본 정보, 평형, 가격 요약, 원천 행과 의견 경로를 담은 상세 DTO |
| `data/apartments/summary/<묶음>.bin` 256개 | 관심 단지와 회원 API에 필요한 이름·지역·평형·최근 거래 요약 |
| `data/apartments/index.json` | 전체 별칭·이전 행 연결과 BIN 해시를 보관하는 생성·검증 기준 |
| `data/apartments/entry-index.json` | entry schema 3의 공통 metadata, 거래 manifest 기준 해시, BIN 해시와 진입 묶음 해시 |
| `data/apartments/entry/<묶음>.json` 64개 | 별칭·이전 행의 단지 ID와 묶음 번호, 실제 원천 지역·번호 연결 |

`js/apartment-entry.mjs`는 작은 `entry-index.json`을 먼저 읽는다. 이어서 선택 ID에 필요한 진입 묶음만 해시로 검증하고 캐시한다. 공통 `updated`, `propertyUpdated`, 원천 해시와 거래 기준 해시는 각 묶음에 반복하지 않는다. BIN 해시도 공통 색인에서 결합한다. 기준일이나 BIN 내용만 바뀌면 진입 묶음 64개를 다시 쓰지 않는다. 별칭이나 이전 행 연결이 바뀌면 해당 진입 묶음만 바뀐다.

`js/apartment-records.mjs`는 필요한 BIN을 내려받아 해시를 검증하고 gzip을 해제한다. 파일과 열린 색인은 제한된 캐시에 보관한다. 선택 DTO는 조회할 때 복원하며 객체 자체를 공용 캐시에 저장하지 않는다. 공통 기준일은 manifest에서 복원한다. 단지별 다른 기준일, 누락 필드와 `null`은 구분해서 보존한다. 기존 JSON DTO와 entry schema 2도 읽을 수 있다.

Rust 생산자는 `propertyUpdated`를 DTO와 단지 index에 같은 null·날짜 값으로 넣는다. 이 공통 필드도 상속 대상이다. 주택 정보 기준일만 바뀌어도 상세 BIN 256개가 모두 바뀌는 일을 막는다.

`tools/build-apartment-records.mjs`는 비공개 포장 캐시를 사용한다. codec 지문과 공통 기준일을 분리한 논리 내용이 같으면 기존 gzip BIN을 재사용한다. 출력 바이트가 같으면 파일을 다시 쓰지 않는다. 원천 해시와 진입 manifest의 연결 검사는 유지한다. 전월세 manifest의 단지 색인 해시와 진입 색인은 최종 BIN 색인에 맞춰 갱신한다.

공식 native 포장은 공통 매매 참조 생성 뒤 `complete-group-sale-areas.mjs`를 실행한다.
검토한 그룹의 누락 평형 요약을 보완한 뒤 기존 512개 BIN에 포장한다.
그룹·원천 평형·관련 지역의 거래 해시·계산 코드가 같으면 보완 요약을 재사용한다.
캐시는 기존 공통 캐시 DB의 `group-sale-supplements-v1` 키를 사용한다.
공통 거래 본문을 다시 만들거나 별도 공개 이력 파일을 추가하지 않는다.

native 생성의 `cacheDir`는 `tools/cache-store.mjs`가 관리하는 가상 경로다. 포장 캐시는 그 경로의 `apartment-records-v1` 키를 사용한다. 기존 공통 `data/housing-cache.sqlite`를 재사용하며 가상 경로 아래에 별도 DB를 만들지 않는다. `cacheDir`가 없는 단독 실행은 출력 작업 공간의 비공개 캐시를 사용한다.

2026-10-23에는 기존 로컬 공개 자료의 단지 20,915개를 격리 출력으로 변환했다. 상세와 요약 각각 256개 파일의 모든 레코드가 원본과 같았다. 재실행은 BIN 512개를 재사용했고 다시 쓰기 0개였다. 별도 회귀에서는 상세 값 1곳 변경 시 BIN 1개만 포장했고, 나머지 511개의 해시와 수정 시각을 유지했다. [전체 대조 결과](../../_ops/reports/packed-transport-20261023/apartment-audit.json)는 일회성 검산 기록이다. 정상 생성이나 서버 시작의 실행 조건으로 쓰지 않는다.

같은 gzip level 6으로 비교하면 상세 합계는 JSON 33,248,351바이트에서 BIN 31,061,328바이트로 줄었다. 요약 합계는 JSON 4,142,993바이트에서 BIN 5,524,405바이트로 늘었다. BIN이 항상 더 작다는 뜻은 아니다. 선택한 단지만 복원하고 바이트·색인을 재사용하는 것이 주된 목적이다. 4개 상세 묶음의 압축 해제부터 첫 선택 복원까지는 Node 표본에서 JSON 7.95~10.29ms, BIN 6.12~9.10ms였다. 요약 표본의 첫 조회는 대체로 비슷했다. [선택 조회 측정](../../_ops/reports/packed-transport-20261023/selected-read-audit.json)은 네트워크와 화면 표시 시간을 포함하지 않는다.

앞선 2026-10-23 격리 검산에서는 공식 native 자료 생성, 운영 자료의 BIN 전환, 배포를 실행하지 않았다. 운영 반영 상태는 [공식 릴리스 기록](../../15_26/docs/site-release-workflow.md)의 run과 같은 SHA의 CI·공개 검증 근거를 따른다.

같은 격리 출력의 Chrome 표본에서는 대흥동세양의 상세 패널과 전체 화면을 확인했다. 이름·주소·세대수·평형·최신 거래·최근 평균·거래 건수가 원본 DTO와 같았다. entry와 선택 BIN을 읽었고 기존 상세 JSON이나 전체 단지 index로 돌아가지 않았다. 두 번째 문서에서는 BIN 추가 다운로드가 없었다. [브라우저 검증](../../_ops/reports/packed-transport-20261023/apartment-cua-result.json)은 상세 화면만 대상으로 한다. 이 부분 출력 서버에는 홈 검색 manifest를 제공하지 않았다.

현재 리뷰 계약에서 상세의 단지 세대수는 해당 공개 항목의 `units`를 따른다. 여러 원천을 묶은 공개 항목의 세대수가 미확인이면 `null`이다. 이 값을 개별 원천 행의 `tu`로 채우지 않는다. 현재 원천 행은 미확인 평형 세대수 `u`를 생략한다. 상세의 평형과 원천 행은 `units:null`로 표시한다.

`npm run test:site`의 자료 검사는 상세 전체를 순회한다. 단지·평형 세대수 범위, 거래 소유 연결, 대표 행 묶음, canonical ID, 원천 행과 `apt_<row id>` 의견 경로를 대조한다. 한 canonical ID에 여러 대표 행 묶음이 있어도 각 원천 행의 의견 경로는 유지한다. 이 검사는 별도 시험이며 생성기나 브라우저의 정상 실행 조건에 넣지 않는다.

`NODO_TEST_DATA_ROOT`를 지정하면 `test-apartment-data.mjs`의 자료 검사를 해당 격리 후보에 실행한다.
미지정 시 저장소 자료를 검사한다. `test:site`는 구성원 선택과 공통 거래 보완의 회귀 시험도 포함한다.

새 경로는 `/apartment/?id=<실제 거래키 또는 publicationId>&area=85&tab=overview`이다. 기존 검색 `#a=...&ar=...`, `#i=...`, 지도 상세 및 K-APT `#k=...` 링크는 새 화면으로 이어진다. `row=0`도 유효한 이전 식별자다.

### 임대 단지 표시

현재 공개 분류가 `tenure:rental`인 아파트는 지도 가격표·겹친 단지 선택 목록,
상세의 상태·매매·투자분석 빈 화면, 관심 목록과 하트 순위에서 `임대 단지`로 표시한다.
전월세 탭의 계약 내역과 조회 조건은 유지한다. 매매가 없거나 전월세 거래만 있다는
이유로 임대 단지로 추정하지 않는다. 상세와 관심 목록은 기존 DTO의 `rental`을 사용한다.

지도는 `data/housing-v3/transport.json`의 `rentalComplexIds`를 공개 단지 ID에 연결한다.
이 목록은 배포 때 현재 공개 분류에서 만든다. 지도 인덱스에 기록된 주택 원문 해시와
manifest의 원문 해시가 같을 때만 사용한다. 다른 단지의 거래 키나 이름으로 대신 연결하지 않는다.
전체 주택 BIN이나 단지별 BIN을 추가로 내려받지 않는다. 표시 변경으로 거래 자료를 재생성하지 않는다.

실제 거래키가 없는 대장상 아파트는 원장에 저장한 영구 대장 식별자로 공개한다.
공개 항목의 `transactionStatus`는 `none`이고 거래키·거래 소유 주장은 비어 있다.
상세와 현재 지도는 `거래 자료 없음`으로 표시한다. 전월세 탭은 이 상태에서 거래
파일을 요청하지 않는다. 이를 임대 단지로 추정하거나 다른 단지 가격으로 채우지 않는다.
현재 지도에서는 면적·가격 조건이 없으면 위치가 확인된 항목을 표시한다. 조건에 필요한
면적이나 가격이 없으면 그 조건의 결과에서 제외한다.

### 공동주택 정보의 전송 형식

직접 접속 가능한 `/kapt-v2.html`은 `data/housing-v3/transport.json`을 읽는다.
schema 1의 `gzip-json-v1` manifest는 원본 JSON의 경로·SHA-256·바이트 수와
`index.<원본 SHA-256>.bin`의 경로·압축 SHA-256·바이트 수를 기록한다.
BIN 내용은 원본 JSON 바이트를 그대로 gzip으로 압축한 것이다.
공통 다운로드 캐시에서 압축 바이트를 재사용한다. 해제 크기와 원본 해시도 확인한 뒤
전체 목록을 한 번 파싱한다. 이 경로는 개별 레코드 색인 조회가 아니다.

생성용 `data/housing-v3/index.json`은 Git과 공식 후보에 남는다. CI는 이 원본을
공개 자산에서만 두 전송 파일로 대체한다. 공개 검증은 원본 SHA와 전송 manifest,
압축 바이트 및 해제 원본 SHA의 연결을 확인한다. 원문은 128MiB까지 허용한다.
생산기·브라우저·공식 공개 검증에 같은 상한을 적용한다.
공개 파일은 기존 20,000개·파일당 25MiB 제한을 유지한다.
같은 원문과 포장 코드의 gzip은 비공개 캐시에서 재사용한다. 출력 바이트가 같으면
파일을 다시 쓰지 않는다. 명명된 BIN에만 1년 immutable 캐시를 적용한다.
manifest는 재검증한다. 로컬·이전 배포에서 manifest가 404일 때만 기존 JSON을 읽는다.
그 밖의 응답 오류·형식 오류·해시 불일치는 JSON으로 우회하지 않는다.

현재 계약에서는 공개 목록 수와 `review.approved`가
참인 개별 검토 승인 수를 구분한다. 유형별 건수는 실제 목록에서 계산한다. 면적별
요약이 없으면 미제공으로 표시하며, 메타데이터만 있는 항목을 임대로 단정하지 않는다.
구 승인 JSON도 지원한다. 아파트의 이전 별칭은 통합 상세로 이어진다.

### 현재 건축물 상태

현재 리뷰의 `building-status.json`은 대장 연결 상태를 표시한다. `active`는 현행
대장 연결, `closed`는 폐쇄·말소 대장 이력, `partial_closed`는 현행과 폐쇄 이력의
혼재 또는 일부 폐쇄, `unknown`은 상태 미확인이다. 현재 계약의
`demolitionConfirmed=false`를 유지한다. 폐쇄·말소를 철거로 바꾸지 않으며,
미확인·일부 폐쇄·폐쇄 항목은 이 상태만으로 기본 목록에서 숨기지 않는다.
상태 파일을 받지 못하거나 현재 계약의 항목이 없으면 현행으로 추정하지 않는다.

`node tools/verify-redevelopment-data.mjs`는 상태와 주택 메타데이터의 계약·원천
버전, 지번별 거래 원천 ID를 대조한다. 현재 계약에 구 멸실 플래그나 철거 확정을
섞으면 실패한다. 기존 재건축 관계의 근거·범위·이전/후속 연결 검사도 유지한다.
현재 거래 index 밖의 이전 단지는 `redevelopment-decisions.json`의 같은 지번 키,
명시 상태·이름, 관계와 일치하는 근거 ID가 있을 때만 역사 관계로 확인한다. 이 판정은
현재 단지의 대장 상태를 덮거나 미확인을 재건축·멸실로 바꾸는 데 쓰지 않는다.
별도 `Verify redevelopment data` CI가 이 검사를 실행한다. Production 빌드는
이 명령을 호출하지 않으며, 현재 상태의 화면 회귀시험은 Production 시험에 포함된다.

공식 Rust [부동산 릴리스](../../15_26/docs/site-release-workflow.md)에서 자료 갱신 후 상세 자료를 생성·검증한다. 매매/전월세 계약 상세는 [공통 거래 참조](../../15_26/docs/housing-packed-storage.md)를 사용한다. 단지 DTO·요약 BIN은 공통 거래 원문을 대체하지 않는다. 사이트 빌드는 원천 해시와 상세 자료가 다르면 중단한다. 브라우저도 단지 및 거래 파일 해시를 검증한다.

### 현재 리뷰 자료의 격리 미리보기

현재 리뷰의 [공개 후보 내보내기](../../ops-dashboard/housing-review/docs/hub-source.md#현재-리뷰의-공개-후보-내보내기)로 새 `_ops` 폴더에 후보를 만든다.

미리보기는 `http://127.0.0.1:8794/map/`이다. 운영 DB·공개 파일·사용자 의견에는 쓰지 않는다.
후보의 `candidateOnly=true`, `approvedOnly=false`를 유지한다. 공개 패키지는 후보 자료를 거부한다.
기존 단지 ID·별칭·평형 행·댓글 ID·가격 통계는 재사용한다. 필지 차이만으로 기존 단지를 나누지 않는다.

## 공통 단지 자동완성과 검색 자료

**화면 동작.**

- 후보는 `송파구 · 리센츠`처럼 시군구를 앞에 두고 둘째 줄에 동을 표시한다. 이름·시군구·동이 겹치면 주소를 추가한다. 지역·시군구 범위의 전체 단지에서 최대 10개를 추천한다.
- 매매·전세·월세의 단지 검색, 지도, 실거래, 기간별 실거래, 통계, 비교와 기존 단지·계약 목록이 같은 모듈을 쓴다. 단지 입력창이 없는 화면에는 검색창을 만들지 않는다. 거래 기간·금액·면적 조건은 후보를 고른 뒤 기존 본문 조회에 적용하며 본문 정렬·자유 입력·평형 검색은 유지한다.
- 단지를 고르면 `searchApt`에 공통 식별자를 저장하고 각 화면은 확인된 원천 식별자로 거래를 좁힌다. 비교 화면은 해당 단지 평형 목록으로 좁힌 뒤 기존 평형 선택을 잇는다. 새로고침·공유·뒤로 가기·거래 유형 전환에서 선택을 복원하고, 입력 수정·초기화는 선택을 해제하며 지역 범위를 벗어난 선택은 해제 안내를 표시한다. 조건에 맞는 거래가 없으면 “단지는 있으나 현재 조회 조건에 맞는 거래가 없습니다”를 표시한다.
- 한글 조합 중에는 검색하지 않는다. 조합 완료·입력 후 150ms 지연, 이전 응답 무시, 방향키·Enter·Escape, 터치, combobox/listbox와 실시간 안내를 지원한다. 첫 후보는 Enter만으로 자동 선택하지 않는다. 자료를 불러오지 못해도 기존 본문 검색을 쓸 수 있고 자동완성 재시도를 제공한다.

**검색 자료.** `tools/build-search-data.mjs`가 빌드·로컬 서버 시작 때 `data/index.json`(평형 행·원천 식별자), `data/apartments/index.json`(공개 식별자 연결·모호한 연결), 매매·전월세 manifest와 지역 번호표·metadata(regionalReader가 현재 공개 형식을 해석하며 과거 catalog.bin 고정 경로를 요구하지 않음), `data/map/index.json`(지도 ID·좌표), `data/housing-v3/index.json`(공개 단지 메타데이터)으로 목록을 만든다. 생성과 검색 Worker는 개별 거래를 읽지 않는다. 연결이 확인된 식별자로만 합치고 이름·좌표 유사도로 합치지 않는다. 연결 미확정 전월세 단지는 `rental:<원천 ID>`로 유지하고 등록된 이름 변형은 별칭에 보존한다. 검토한 공개 그룹은 기존 대표 ID로 검색하며 원래 단지명은 별칭이다. 홈의 평형별 표는 원천 행과 투자지표를 유지하고 통합 표는 그룹 이름과 중복 제거한 전체 세대수를 쓴다. 그룹 세대수가 미확인이면 원천 세대수를 더해 채우지 않는다. 홈 최신 요약의 `publicationGroup`이 이 표시 규칙을 구분한다.

자동완성과 홈 최신 요약은 각각 32개 버킷이며 단지 ID의 SHA-256 첫 바이트를 32로 나눈 나머지가 번호다. 단지가 추가돼도 기존 ID의 버킷은 바뀌지 않는다.

| 파일 | 역할 |
| --- | --- |
| `data/search/apartments.json` | 자동완성 manifest. `schema:1`, `format:gzip-json-records-v1`, 버전·버킷 경로·입력/출력 해시·해제 바이트 수 |
| `data/search/catalog/<버킷>-<SHA-256>.bin` | 자동완성 단지 레코드 32개 |
| `data/search/latest-index.json` | 홈 요약 manifest. 같은 형식과 기준일·검색/전월세 버전·해시 |
| `data/search/latest/<버킷>-<SHA-256>.bin` | 단지 정보와 최신 전세·월세 가격 32개 |

파일명은 압축 내용의 SHA-256을 포함한다. 확장자는 `.bin`이나 풀면 `{단지 ID: 레코드}` UTF-8 JSON이며 `PGRCD001` 단지 DTO와 다른 형식이다. `rawBytes[path]`는 해제 바이트 수이며 reader가 실제 크기와 대조한다. `inputs`는 원본 파일과 해시, `sources`는 생성 gzip 경로와 해시다. 포장 단계는 `inputs`를 실제 원본 자산 해시와 대조한다. `tools/packed-asset-cache.mjs`는 비공개 캐시에 버킷별 논리 내용·직렬화/압축 코드 지문·출력 해시를 저장하며 근거와 저장 바이트가 맞으면 포장을 생략한다. 한 단지가 바뀌면 그 버킷만 다시 포장한다. 목록 구성과 입력 확인 자체는 생략하지 않는다. 전송 형식은 gzip JSON으로 정했다. 같은 32개 버킷·같은 값에서 generic ValueNode BIN보다 작고 최초 전체 읽기가 빨랐으며, 현재 검색처럼 전체 객체를 만드는 소비 경로에서는 BIN의 선택 복원 이점이 없다. 이 결론을 공통 거래의 전용 BIN 스키마나 단지 상세의 선택 조회로 일반화하지 않는다.

[es-hangul](https://github.com/toss/es-hangul) 2.4.0을 정확히 고정해 초성 추출·자모 분해에 쓰고 Worker 번들에 포함해 자체 제공한다. 순위는 `js/apartment-search-model.js`가 계산한다. 순서는 정확 일치, 앞부분, 부분, 초성·입력 중 자모, 가벼운 오타다. NFKC·대소문자·공백·괄호 차이는 정리하되 숫자와 괄호 안 단어는 남긴다. 여러 단어는 모두 이름·별칭 또는 지역·주소와 맞아야 하며 지역에는 오타를 허용하지 않는다. 이름 오타는 한글 3음절 이상, 자모 편집거리 비율 0.25 이하다. 명시한 단지·차수 번호가 다른 후보는 제외한다. 동순위는 거리·길이 차이·이름·주소·식별자로 안정 정렬하며 백분율 점수를 표시하지 않는다.

문서당 Worker 하나가 첫 검색에서 `packedDataset.all()`로 32개 버킷을 읽어 색인을 만들고 같은 문서에서 재사용한다. `packedDataset`은 파싱한 버킷을 최대 4개·해제 바이트 합계 64MiB(검증한 `rawBytes` 기준)로 LRU 보관하고 호환 BIN 경로는 열린 버퍼와 색인만 보관한다. 공용 검증 파일 캐시는 압축 바이트를 최대 256개·64MiB까지 Cache Storage에 두며 이 한도는 JS 힙 상한이 아니다([공통 자료 계약](site-layout.md)). Worker는 `apartments` 배열 JSON과 `packed-records-v1` 버킷도 읽으며 현재 리뷰 후보 미리보기는 JSON 배열 경로를 유지한다.

**홈 단지·평형 목록.** 매매·전세·월세는 기존 스크리너의 표·카드·검색·정렬·페이지·평형 통합을 쓴다. 원본 매매 행 번호와 계산 지표를 유지하고 승인된 공통 카탈로그로 전월세 전용 평형을 추가하며 이름·좌표로 연결하지 않는다. 거래가 없는 유형은 ‘거래 없음’으로 표시하고 정렬 마지막에 둔다. 전월세 전용이라는 이유로 임대 단지로 분류하지 않는다. `build-search-data.mjs`가 `build-home-search-data.mjs`를 호출해 최신 전월세 상태 스냅샷의 opening/updates를 접어 최신 유효 계약을 고른다. 단지·반올림 평형·유형별 최신 계약일, 동률이면 원천 거래 ID 순이며 환산율이 없으면 원금액만 표시한다. 브라우저는 처음 전체 필터 목록을 만들 때 32개 버킷을 모두 읽고 동일 입력 해시의 매매 인덱스도 검증한다. 동시 호출·탭 전환은 같은 Promise를 재사용하며 홈은 과거 월 파일이나 전체 계약 이력을 받지 않는다. 지역·동·단지·면적·세대수·준공연도는 공통이고 가격 범위·정렬은 유형별 URL/로컬 상태다. 지도에서 저장한 과거 날짜는 홈 조회에 쓰지 않으며 전월세에는 매매 투자지표 필터를 적용하지 않는다. 상세는 기존 패널을 열고 연결 미확정 ID는 공통 카탈로그의 정확한 원천 ID만 써서 전월세 이력을 조회하며 다른 단지로 대체하지 않는다.

**현재 리뷰 후보 검색.** `tools/prepare-current-review-search.mjs`가 후보의 평형 행·상세 식별자·지도·단지 정보와 기존 공개 매매·전월세 번호표만 합쳐 후보 폴더 `data/search/apartments.json`에 단지 배열 JSON으로 저장한다(후보는 32개 gzip 버킷 포장으로 전환하지 않음). 거래 내역은 읽지 않으며 같은 공개 단지의 여러 원천·필지는 기존 식별자 연결을 유지한다. 현재 원천·지역 근거가 없는 보존 단지는 “지역 미확인”으로 남기고 지역을 추측하지 않는다. 후보는 `_ops` 아래 별도 폴더여야 하며 manifest의 `candidateOnly`는 `true`, 주택 메타데이터는 `candidateOnly:true`·`approvedOnly:false`여야 한다. 운영 검색 생성기는 후보를 받지 않는다.

```text
node tools/prepare-current-review-search.mjs D:/Work/sudoapthistory CANDIDATE_DIRECTORY
```

미리보기 `http://127.0.0.1:8794/map/`은 후보 파일을 우선하고 나머지 공유 거래 파일은 기존 소스에서 읽는다. HTML·JS·CSS는 현재 소스이며 GET·HEAD만 허용한다. 로그인 API와 운영 쓰기는 연결하지 않고 “현재 리뷰 데이터 미리보기 · 운영 미반영”을 표시하며 내부 evidence·manifest는 제공하지 않는다. 타임라인 후처리는 후보의 일별·전월세 manifest를 현재 지도 버전에 연결하고 검색 목록에 실제 제공하는 두 manifest 해시를 넣는다. 거래 파일·원천 revision·번호표·가격 통계는 바꾸지 않으며 기존 공개 단지 ID가 빠졌거나 지도 참조 외 변경이 있으면 중단한다. 이전 검색·지도 가격 캐시·외곽선은 후보 대신 제공하지 않으며 후보에 가격 캐시가 없으면 공유 거래로 조회한다. 합친 외곽선은 `data/map/boundaries/{g}.json`에 두고 상세 DTO의 `map.boundary`가 참조하며 검색 목록에는 도형을 복제하지 않는다. 후보 경계가 없거나 해시가 다르면 준비를 중단한다. 외곽선 생성·표시는 [지도 문서](map-explorer.md)를 따른다. 전용 검증은 `node --test tools/test-prepare-current-review-search.mjs tools/test-prepare-current-review-timeline.mjs tools/test-preview-current-review.mjs`다.

정식 현재 리뷰 계약의 Node 지원은 구현했으나 운영 전환은 적용하지 않았다. 정식 자료는 주택·지도 메타데이터의 `contract`가 모두 `current-review-publication-v1`이고 `candidateOnly`가 모두 `false`이며 주택 `approvedOnly`가 `false`, 주택 `sourceVersion`과 지도 `publicationSourceVersion`이 같아야 한다(지도 `sourceVersion`은 최종 행정 구역 연결까지 반영한 별도 버전). 기존 공개 형식은 `approvedOnly:true`를 유지한다. 정식 상세 생성은 생산자가 준비한 version 2 DTO를 재사용하며 `--verify`일 때만 기존 상세 검증을 실행한다. 정식 검색은 후보와 같은 “지역 미확인” 처리를 쓰되 현재 원천이 없다고 명시된 거래 없는 보존 단지에만 허용하며 거래 원천의 지역 누락은 오류다. 생산자 검증의 `checks.currentReview`는 계약·원천 버전·주택/지도 파일 해시와 `individualApprovals: preserved_from_workbench`를 보존하고, 최종 `verify-housing-regions.mjs`가 실제 파일의 계약·버전 연결로 이를 구성한 뒤 완료 기록 작성 때 manifest 해시와 다시 대조한다. 일별·전월세·거래 상세·단지 DTO 검증은 그대로 필요하며 이전 `buildingAudit` 성공 결과를 대신 넣지 않는다. 후보 자료나 서로 다른 원천 버전은 완료 기록을 만들 수 없다. CLI는 일반 경로와 Windows 확장 경로(`\?\D:\…`)를 같은 파일 URL로 판정하며 import 때는 자동 실행하지 않는다. 관련 독립 검증은 `node --test tools/test-verify-housing-regions.mjs tools/test-housing-publication-contract.mjs tools/test-cloudflare-apartment-sale.mjs tools/test-validation-session.mjs`다.

**검증과 예약 배포.** `npm run test:search`(정규화·순위·초성·혼합 자모·오타·지역 조합·번호·동명 단지·후보 제한, 실제 자료, 연결 분리, 평형 중복 제거, 조건 적용, 키보드, 한글 조합, 응답 순서 경합, URL 복원, 오류/재시도)와 `node --test tools/test-cloudflare-packed-assets.mjs tools/test-cloudflare-home-search.mjs`(내용 해시 버킷 재사용, 홈/자동완성 번들, 재시도, 버퍼 개수·용량 제한, 원본 행·식별자 보존)를 쓴다. 로컬 실행은 `npm ci` 후 `npm run preview`(`http://127.0.0.1:8793`)이며 검색 모델·원본 자료를 바꾸면 서버를 다시 시작한다. 운영·시험 배포 모두 `test:search`를 실행한다. 실제 카탈로그 검사는 고정된 단지 수를 전제하지 않고 해당 빌드의 매매·전월세 원천 전체가 들어 있는지 대조한다. 공개 gzip JSON 버킷·manifest·Worker는 `cloudflare/dist/public`에, 버킷 재사용 근거는 `cloudflare/dist`의 비공개 캐시에 둔다. 원본 자료나 Git 추적 파일을 생성 결과로 덮어쓰지 않으며 별도의 검색 자료 생성 예약은 필요 없다.
