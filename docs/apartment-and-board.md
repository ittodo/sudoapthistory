# 통합 아파트 상세와 공용 게시판

## 구현

- 모든 공개 페이지에서 공통 메뉴와 라이트·다크·시스템 테마를 사용한다.
- 검색·비교·실거래·지도·단지정보에서 아파트 선택 시 `/apartment/`로 이동한다. 전월세는 확인된 기존 aptSeq가 있는 단지만 연결한다.
- 상세는 개요, 실거래, 투자분석, 단지정보, 위치, 의견 6개 탭이다. 평형과 탭을 URL에 저장한다.
- 최신 유효 거래와 최근 평균가의 기간·건수를 각각 표시한다. 해제·원천에서 사라진 거래는 통계에서 제외하되 내역에서 확인할 수 있다.
- 단지 전체 세대수와 선택 평형 세대수를 구분한다. 여러 원천이 연결된 단지의 미확인 주차·용적률·평형 세대수는 임의 합산하지 않는다.
- 기존 `apt_<row id>` 의견을 그대로 조회한다. 여러 원천 평형이 연결된 경우 의견 원천을 선택한다.
- `/board/`에서 제목·내용 검색, 글 작성·수정·삭제, 댓글을 제공한다. 운영자는 공지 고정과 글 숨김·복구를 할 수 있다.
- 읽기는 공개, 쓰기는 기존 로그인·닉네임·CSRF·속도 제한·탈퇴 처리 정책을 따른다. 글 제목은 기존 댓글 본문의 첫 줄에 저장해 탈퇴 시 기존 삭제 정책을 적용한다.

## 자료와 호환 URL

`npm run build:apartments`는 공개된 원천 파일만 읽어 조회 인덱스와 256개 JSON 조각을 만든다. 원본 DB와 연결 승인 상태를 수정하지 않는다. 승인된 publication만 단지 합치기에 사용하며 충돌한 연결은 별도 원천으로 남긴다.

새 경로는 `/apartment/?id=<aptSeq 또는 publicationId>&area=85&tab=overview`이다. 기존 검색 `#a=...&ar=...`, `#i=...`, 지도 상세 및 K-APT `#k=...` 링크는 새 화면으로 이어진다. `row=0`도 유효한 이전 식별자다.

`D:/Work/15_26/site_release.py`에서 자료 갱신 후 상세 자료를 다시 생성·검증하도록 연결했다. 사이트 빌드는 원천 해시와 상세 자료가 다르면 중단한다. 브라우저도 조각 및 거래 파일 해시를 검증한다.

## 로컬 확인

```text
npm run build:apartments
npm run typecheck
npm run test:site
npm run test:api
npm run build
npm run preview
```

미리보기는 `http://127.0.0.1:8793`이다. `/__preview/login`은 임시 DB의 테스트 계정으로 접속한다. 운영 로그인·사용자 DB와 연결되지 않으며 서버 종료 시 테스트 글은 사라진다. 이 도구는 공개 자산에서 제외된다.

## 운영 적용 순서

1. 검토된 변경을 `cloudflare-staging`에 배포한다. 기존 Staging workflow가 `0003_board_pins.sql`을 적용하고 테스트·빌드·배포 검증을 수행한다.
2. 스테이징에서 로그인, 글 작성, 다른 계정의 수정 차단, 공지·숨김·복구, 아파트 링크·뒤로 가기를 확인한다.
3. 동일한 검토 변경을 `main`에 반영한다. 2026-09-15 사용자 승인에 따라 Production workflow가 기존 GitHub 배포 토큰으로 `ensure-cloudflare-board-schema.mjs`를 실행한다.
4. 이 도구는 지정된 운영 계정·DB·main 실행과 기존 0001/0002 적용 상태를 확인한 뒤 `0003_board_pins.sql`의 고정된 CREATE TABLE 하나만 실행한다. 다른 SQL로 바뀌면 중단한다. 이미 있는 테이블은 열·외래키를 검증하고 보존한다. 테이블 추가 후 기록 단계가 중단돼도 재실행할 수 있다.
5. 공지 테이블 확인 후 Worker를 배포하고 공개 `/board/`, `/api/board/posts`, `/apartment/?id=41281-3250`와 동일 배포 SHA·자료 해시를 확인한다.

운영의 일반 마이그레이션 자동 실행은 여전히 사용하지 않는다. 이번에 명시 승인된 공지 테이블 추가만 예외이며 회원·댓글 내용, 다른 테이블, 인증 비밀값은 수정하지 않는다.

복구 시 이전 호환 Worker와 정적 자산을 사용하며 D1은 되감지 않는다. 새 테이블은 이전 코드와 공존하므로 삭제할 필요가 없다.

## 이번 검증 범위

로컬 API 권한·공지·숨김·탈퇴 마스킹 테스트, 상세 집계·식별자 테스트, 기존 사이트 배포 검사, 자료 재생성 일치 검사, 생산자 배포 절차 테스트를 통과했다. 브라우저에서 390px 모바일, 밝은/어두운 테마, 상세·거래·의견, 검색 왕복, 게시판 작성·댓글·공지·수정을 확인했다.

운영 D1 변경과 원격 배포는 로컬 검증과 구분한다. 이 문서는 원격 배포 완료 기록이 아니다.
