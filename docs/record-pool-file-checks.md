# 공통 거래 번호 풀의 파일 검사

## 먼저 따를 실행 지침

- 변경분을 한 번 확정하고 영향 자료만 갱신한다. 새 검사기는 기존 공통 거래 번호·평형·중복 건수·취소 상태·압축 월별 바이트를 바꾸지 않는다. 실제 파일 해시 검사를 생략하지 않는다.
- 공식 지역 생성은 기존 housing-record-pool.mjs CLI의 병렬 경로를 사용한다. 출력 검사는 최대4개 worker, 각 worker의 JS heap64MiB/young16MiB로 제한한다. 인라인 Node 실행 옵션은 상속하지 않는다.
- 잠금 아래 현재 원천 해시와 이전 번호 풀의 실제 파일 해시를 확인한다. 검사 결과 객체는 이번 Node 프로세스에서만 사용하고 외부 JSON의 PASS를 검사 권한으로 받아들이지 않는다.
- 재사용 직전에는 같은 파일의 크기·수정/변경 시각·inode가 검사 시점과 같은지 확인한다. 전체 저장이 끝난 뒤 이번 프로세스가 실제 바이트를 검사했고 stat이 그대로인 출력은 같은 메모리 객체를 재사용한다. 신규/변경 출력만 실제 바이트를 병렬 검사하고 원천도 재확인한다. 링크·경로 이탈·파일 교체·손상은 재사용을 차단한다.
- 새 검사 코드 지문으로 기존 receipt를 임의 승격하지 않는다. 코드가 달라져 최초 번호 풀을 다시 구축하는 비용은 정상 미변경 재사용과 구분한다. 번호 풀 자체는 비공개 캐시이며 Git·공개 자산에 포함하지 않는다.
- inputs/outputChecks/build/finalBytes와 지역별 actual seconds를 각각 남긴다. NODO_RECORD_POOL_TIMINGS=1을 사용하면 공식 Rust 부모가 stderr를 즉시 전달하고 stage 로그에도 저장한다. 종료 코드0·구간PASS는 전체 후보·소비ack·공개 승인이 아니다.
- 비용이 커지면 해당 구간에서 중단하고 증거를 보존한다. 같은 기준 시간 측정 때문에 전체 prepare를 반복하지 않는다. 운영 DB·승인·백업·서버·공개본은 이 읽기 전용 점검 때문에 수정하지 않는다.
