## 앞으로 지킬 배포·검증 규칙

가격 계산의 영구 캐시는 `cloudflare/dist/housing-cache.sqlite`다. CI는 이 비공개 DB 한 개를 복원·저장한다. 매매·전세·월세 지역 가격과 임대 시장 통계는 `calculation_cache`의 서로 다른 scope를 사용한다. 입력·계산 코드 의존성과 결과 해시를 유지한다. 변경된 묶음만 다시 계산한다. 손상된 캐시 항목은 재계산하며 원천 오류는 숨기지 않는다. 공개용 압축 파일은 DB에서 출력한다. 출력 파일이 손상됐어도 DB 결과가 정상이면 다시 계산하지 않고 출력만 복원한다.

단지·임대 시장의 BIN 포장과 검색·지역 가격의 gzip JSON 포장은 같은 비공개 캐시 계층을 사용한다.
계산 결과와 전송 형식의 지문은 구분한다. BIN 포장 지문에는 코덱과 생성된 PolyGen 열을
포함한다. JSON 포장은 해당 직렬화·압축 코드의 지문을 사용한다. 같은 논리 내용과 포장 지문이면 압축 결과를 재사용한다. 최종 파일의 바이트가
같으면 다시 쓰지 않는다. 최초 형식 전환은 새 포장이 필요하다.

검색의 `data/search/catalog/`와 `data/search/latest/`는 각각 32개 gzip JSON 버킷이며
manifest의 `format`은 `gzip-json-records-v1`이다. `.bin` 파일명에는 내용 SHA-256을 넣는다.
이 두 경로에만 1년 `immutable` 캐시를 적용한다. 작은 JSON manifest와
고정 이름 BIN은 Cloudflare 기본 재검증을 유지한다. 자료 URL에 이미 SHA-256 `v`가
있으면 `deployment-version.js`가 이를 배포 SHA로 덮지 않는다. 관련 없는 코드 배포로
검증된 자료의 캐시 키를 바꾸지 않기 위한 규칙이다.
[형식 선택과 최초 전체 읽기 측정](apartment-search.md#전송-형식-선택-근거-2026-10-23)은 검색 기준 문서에 둔다.
[Cloudflare 정적 자산 헤더 규칙](https://developers.cloudflare.com/workers/static-assets/headers/)을 따른다.
파일 수 20,000개와 파일당 25MiB 검사는 그대로 적용한다.

브라우저의 매매·전월세 공통 Cache Storage는 256파일·압축 바이트 64MiB를 제한으로
사용한다. 저장 순서에 따라 오래된 항목을 정리한다. 같은 실행환경의 진행 중 요청과
창·Worker 사이의 완료 파일을 재사용한다. 개인 API 응답은 이 캐시에 넣지 않는다.

전월세 시장 통계는 파일 변경과 계산 입력 변경을 구분한다. 거래 파일과 기존 번호표 구간이 같으면 해석·집계를 생략한다. 번호표 끝에 매매 면적이 추가돼도 기존 통계는 유지한다. 분기 파일이나 지역 귀속이 바뀌면 해당 월을 읽고 실제 집계 입력을 비교한다. 면적·보증금·월세·계약 구분·환산율·시도·시군구가 같은 월은 집계를 재사용한다. 행 순서와 중복 건수도 비교한다. 취소 거래는 기존 규칙으로 제외한다. 현재 물리 파일 해시와 실행 종료 시 입력 확인은 유지한다. 자세한 기준과 실측은 [전월세 시장 캐시](rental-market.md#자료와-캐시)를 따른다.

로컬 파일 포장은 지역 거래·상태, 매매 상세, 전월세 상세, 계약 이력의 생산 코드 지문을 따로 저장한다. DB 잠금이나 통계 화면 수정만으로 모든 포장 범위를 무효화하지 않는다. 현재 입력·번호표·결과 바이트와 DB 변경 묶음은 계속 확인한다. 새 범위별 근거가 없는 기존 캐시는 최초 실행에서 다시 구축한다. [파일 생산 의존성](../../15_26/docs/file-production-code-dependencies.md)이 기준이다.

로컬 생성기는 `NODO_CACHE_DB`로 `15_26/data/housing-cache.sqlite`를 지정한다. CI는 자체 DB를 사용한다. 전유부 원문·내부 연결·의견·승인 원장을 CI에 업로드하지 않는다. 검증 재사용 기록은 같은 DB의 `cache_artifact`에 저장한다. `cloudflare/dist/validation-cache-v1`은 논리 scope이며 별도 폴더 캐시는 복원·저장하지 않는다. 주간 완료 기록은 실행 이력으로 유지한다.

`tools/cache-store.mjs`는 로컬 지역 입력·번호 풀·계산·포장 캐시와 검증 재사용 기록의 DB 접근을 맡는다. `cache_artifact`는 경로별 참조를, `cache_blob`은 같은 해시의 내용을 한 번 저장한다. 압축된 payload는 조회할 때 기존 바이트로 복원한다. 마지막 참조를 교체·삭제하면 사용하지 않는 payload도 같은 트랜잭션에서 제거한다. 공개 출력은 실제 파일로 쓴다. DB에 없는 항목을 옛 캐시 파일에서 읽지 않는다. Node 종료 시 연결을 닫아 WAL을 반영한 뒤 CI가 DB를 보관한다. 로컬 거래 대표값의 이전·축소·반영·복구와 실제 적용 상태는 [공통 캐시 DB 기준](../../15_26/docs/calculation-cache-candidate.md#공통-캐시-db의-저장-범위)을 따른다.

Node 22는 SQLite 모듈을 불러올 때 실험 기능 경고를 출력한다. 지역 검증기의 import가 CLI를 실행하지 않는지 확인하는 테스트는 해당 자식 프로세스에서만 `ExperimentalWarning`을 억제한다. 종료 코드와 빈 표준 출력·오류 검사는 유지한다. 지역 검증 테스트의 임시 폴더는 캐시 DB 연결을 닫은 뒤 정리한다. 실제 CLI 검증과 운영 빌드의 경고·오류 처리는 바꾸지 않는다.

manifest 해시 확인은 같은 호출에서 동일 경로를 한 번 읽고, 모든 참조의 예상 해시를 각각 대조한다. 호출 종료 전 파일 식별자·크기·수정/변경 시각과 상위 디렉터리 식별자를 다시 확인한다. 호출 간·실행 간 파일 검사 생략은 하지 않는다. 검사 코드 변경은 기존 의미 검사 증거를 무효화하므로 최초 정식 CI는 현재 코드로 다시 검증한다. 기존 producer 증명을 재서명하지 않는다.

공식 부동산 생성의 비공개 공통 거래 번호 풀은 [record-pool-file-checks.md](record-pool-file-checks.md)의 현재 바이트 병렬 검사 경로를 사용한다. 공개 파일/CI 가격 모델·schema를 바꾸지 않으며, 검사 코드가 바뀐 최초 캐시 구축과 정상 재사용 시간을 구분한다. 구간PASS를 새 자료 공개 승인으로 해석하지 않는다.


운영 빌드는 현재 파일 해시와 검사 코드 지문을 확인한 PASS 증거를 재사용한다. 변경·누락·손상은 재검사한다. 매매·전월세 공통 거래는 지역·월, 상세는 각각 지역·연도와 지역·월 단위로 검사한다. 수동 workflow 실행은 `NODO_FULL_VERIFY=1`로 전체 의미 검사를 수행한다. 한국 시간 일요일의 전체 검증은 같은 주·같은 검사 코드에 대해 한 번 성공한 뒤 반복하지 않는다. 완료 기록이 없거나 손상·코드 변경이 있으면 전체 검증이 필요하며, 일반 실행의 현재 입력·출력 해시와 변경 구간 검사는 계속 수행한다. 일반 코드 테스트와 동일 SHA·Worker·공개 manifest·공개 바이트 검증은 유지한다. 단계별 실제 시간은 CI artifact의 `build-timings.json`을 확인한다. 공식 생성기가 검토 산출물에 기록한 비공개 `data/.housing-validation.json`도 재사용한다. 검사 코드와 현재 manifest·참조 파일·상세 조각의 모든 바이트 해시가 일치해야 한다. 기록이 없거나 유효하지 않으면 전체 의미 검사 또는 기존 PASS 캐시 검사를 수행한다. 이 기록은 공개 자산에 포함하지 않는다.


- `main` push → Cloudflare Production: 운영 환경 검사 → 타입·기능·자산 검사 → Worker/정적 자산 배포 → 같은 SHA·manifest·공개 파일 해시·없는 JSON 404 확인 → Google 로그인 시작 확인.
- 연도별 지도 상태가 있으면 공개 검사에서 파일 앞 12바이트를 Range로 요청한다. 206 상태, 정확한 범위·길이와 묶음 식별자를 확인한다. 전체 200 응답은 구간 전송 성공으로 처리하지 않는다. 자산 바인딩의 길이 헤더가 없어도 묶음 헤더로 처리하는 기준은 [지도 상태 저장 계약](../../15_26/docs/housing-packed-storage.md#지도-상태의-연도-묶음)을 따른다.
- `cloudflare-staging` push → Cloudflare Staging: 시험 DB와 Worker만 사용한다. 운영 활성화 여부는 시험 대상 검사의 조건이 아니다.
- 운영 배포는 일반 DB migration, 데이터 초기화, secret 생성/교체를 하지 않는다. 현재 Production YAML에 명시된 승인된 board/member-library 테이블·키 검사는 고정된 대상과 검사 코드를 따르며, 기존 상태를 보존한다. 이 문서는 추가 스키마 승인이 아니다. 현재 D1과 기존 회원/관리자/세션을 보존한다. 스키마 변경은 별도 절차가 필요하다.
- 운영 `AUTH_ENABLED=true`, `MAINTENANCE=false`, `WITHDRAWAL_ENABLED=true`를 소스에 저장했다. 배포마다 임시 옵션으로 켜는 방식은 종료한다.
- Cloudflare Custom Domain과 www 리디렉션은 대시보드에서 관리한다. Wrangler `routes`/`route`는 지정하지 않는다. 설치된 Wrangler는 custom domain 목록이 비어 있으면 도메인 게시를 실행하지 않는다. 배포 후 실제 운영 도메인 접근으로 연결 보존을 검증한다. CI 토큰에 DNS·결제 권한을 추가하지 않는다.
- `tools/deployment-provider.json`과 저장소 변수 `NODESTREAM_DEPLOYMENT_PROVIDER`는 `cloudflare`다. 기존 Pages 완료 후 캐시 Purge 작업은 건너뛴다. GitHub Pages와 Supabase 자체는 아직 삭제하지 않는다.
- 무료 플랜 유지. 운영 환경은 `main`, 시험 환경은 `cloudflare-staging`만 허용한다. 수동 검토자·승인 대기 시간을 추가하지 않는다.
- 빈 DB·비공개 Worker를 전제로 했던 일회성 `cloudflare-prepare-production.yml`은 제거했다. Git 이력에서 확인 가능하며 공개 이후 재실행하지 않는다.
- 수집 일정과 공개 데이터는 이번 연결 작업에서 재생성하지 않는다. 생성기는 공통 provider 계약을 읽어 Cloudflare 공개 검증 경로를 사용해야 한다.
- 6시간 주기 Health는 별도 활성 변수로 켠다. 자동 비용 측정은 구현되어 있지 않으며 무료 플랜에 유료 가입이나 비용 차단을 추가하지 않는다.

운영 환경 변수: `CLOUDFLARE_PRODUCTION_ENABLED=true`, `CLOUDFLARE_PRODUCTION_AUTH_APPROVED=true`, `CLOUDFLARE_PRODUCTION_WRITES_APPROVED=true`, 기존 계정/D1 ID와 `CLOUDFLARE_WORKERS_PLAN=free`.

전월세는 사용자 결정(2026-10-03)에 따라 기존 원천별 대표가격·가중치·건수·지역 귀속을 유지한다. 승인된 공개 단지별 내부 캐시에는 소속 원천의 기여 자료를 함께 저장하되 집계할 때 원래 원천 순서를 복원한다. 공개 단지로 가격을 하나로 합치거나 지역 간 원천의 기존 집계 귀속을 변경하지 않는다. 매매는 기존 공개 단지 그룹 계산을 유지한다. 승인 연결 변경은 관련 묶음을 무효화하며 원천 번호·승인 자체는 변경하지 않는다.

지도 가격의 내부 캐시는 위의 비공개 SQLite DB를 사용한다. `cloudflare/dist/region-price-cache-v2`는 공개 파일을 포장하기 위한 출력 위치다. 해당 월의 실제 번호·정확 면적·공개 연결과 가격 입력이 같으면 기존 압축 결과를 재사용한다. 단지 추가·표시 정보 변경 때문에 모든 과거 가격 계산을 다시 하지 않는다. 입력이 바뀐 월은 그룹별 가격 증거를 대조하며 현재 월 파일 해시로 영향 받은 분기만 묶는다. 공개 경로·schema는 유지한다. 현재 입력의 해시를 확인하고 실행 중 변경되면 빌드를 차단한다.

전세·월세는 동일 지역·월의 조립한 상태를 한 달까지만 공유한다. 낮은 단계의 해석한 분기·연간 상태는 CI에서 유형별 추정 보관 비용 1GiB·최대 1,024항목의 LRU 캐시를 사용한다. 연간 상태는 압축 열과 월별 참조 배열의 실제 보관 형태로 비용을 추정한다. 다른 판독기의 기본 네 항목 정책은 유지한다. 현재 물리 파일 해시는 실행 내 공유하고 종료 전에 다시 확인한다. `rentalStateParses`는 지역·월 조립 횟수이며 실제 물리 파일 해석·재사용은 `regionPriceStats.housingDecodeCache.sale/rental`의 hits/misses/evictions와 추정 보관 비용으로 확인한다. RSS는 별도 실측한다. [실행 지침과 구간 근거](../../15_26/docs/generation-storage-cache.md)를 따른다.

`build-timings.json`의 `regionPriceStats`에서 계산/재사용 그룹 수와 가격 재계산 없이 표시 정보만 갱신한 decoratedGroups, 월·분기 재사용과 무효화 원인(missing/inputs/engine/corrupt)을 확인한다. 처음 캐시를 구축한 비용과 이후 변경 입력의 빌드 시간을 별도로 보고한다. 그룹 수는 고유 단지 수가 아니라 그룹·월·뷰의 계산/검증 단위 수다. 그룹·월 증거는 공개 자산이나 Git에 넣지 않는다. 현재 내부 캐시는 약 2.17GB이며 공개 업로드와 별개다. CI 캐시 복원·저장 전송량과 시간도 전체 배포 시간에 포함해 관찰한다. 원천 오류를 캐시 손상처럼 처리하거나 전체 검사 모드를 우회하지 않는다.

### 일요일 전체 검증 완료 기록

`cloudflare/dist/weekly-verification-v1`은 비공개 CI 캐시다. 전체 빌드와 같은 SHA의 공개 manifest·Worker 확인, 인증 시작 검사가 모두 성공한 뒤에만 완료 기록을 저장한다. 선택 기록이나 실패 빌드를 성공 기록으로 바꾸지 않는다. 한국 시간 일요일을 주의 경계로 사용하며 수동 실행은 완료 기록이 있어도 전체 검사한다.

캐시를 처음 전환하는 실행은 같은 주의 공식 Cloudflare Production push/main 성공 증명을 읽어 완료 기록을 복원할 수 있다. GitHub Actions API의 실행·artifact 메타데이터, 원본 ZIP SHA-256, 당시 검사/가격 계산 코드의 Git blob, 같은 SHA의 공개 manifest·Worker 증명이 현재 계약과 모두 같아야 한다. 원본 ZIP은 수정하지 않는다. 검사 코드가 달라지거나 증명·API가 없으면 전체 검증이 필요하다. 이 과거 증명은 주간 계산 재검사의 중복을 줄이는 근거이며 **새 배포 SHA의 공개 승인·검증을 대신하지 않는다**. Actions 권한은 읽기 전용이다.

새 `build-timings.json`은 실제 실행의 `fullVerification`과 `verificationEngine`을 기록한다. 지역 캐시와 완료 기록은 공개/Git에 포함하지 않는다. 새 계산 로더·검사 의존성을 추가하면 주간 검사 코드 목록도 검토한다. 전체 준비·기준 측정을 반복하기 전에 비용이 큰 구간부터 시험한다.

### 복사본 성능 시험

`node tools/benchmark-region-prices.mjs --root FIXTURE --report NEW_JSON`으로 전체 가격 파일의 이번 시간·해시·재사용 수를 남긴다. `--reference`는 기존 모델 계산, `--compare REFERENCE_JSON`은 모든 공개 분기 압축 해시 비교다. 기존 보고서를 덮어쓰지 않는다.

`node tools/benchmark-region-price-changes.mjs --root FIXTURE --report NEW_JSON`은 `fixture.json`에 `isolated:true`인 공개 입력 복사본에서만 번호 추가·신규 거래·가격 정정과 기존 모델의 변경 분기 비교를 수행한다. 운영 사이트·DB 루트는 거부한다. 시험 데이터는 finally에서 복원하지만 프로세스가 강제 종료되면 해당 시험 복사본을 보존하고 조사한다. 시험 캐시·합성 거래를 운영으로 복사하거나 공개하지 않는다. 큰 JSON 보고서·로그는 전체를 터미널에 출력하지 않고 필요한 상태·시간·오류 필드만 읽는다. 한 줄 JSON 로그에 Get-Content -Tail을 사용하면 완료된 작업의 로그 표시만 오래 남을 수 있으므로 실제 result의 완료 상태와 프로세스를 따로 확인한다. `--months`를 사용한 수치는 해당 구간의 시험이며 전체 CI 시간으로 해석하지 않는다. 입력 복사와 최초 캐시 구축 비용은 변경 입력 계산 시간과 분리한다.
