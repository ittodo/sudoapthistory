## 앞으로 지킬 배포·검증 규칙

운영 빌드는 현재 파일 해시와 검사 코드 지문을 확인한 PASS 증거를 재사용한다. 변경·누락·손상은 재검사한다. 매매·전월세 공통 거래는 지역·월, 상세는 각각 지역·연도와 지역·월 단위로 검사한다. 수동 workflow 실행과 한국 시간 일요일 실행은 `NODO_FULL_VERIFY=1`로 전체 의미 검사를 수행한다. 일반 코드 테스트와 동일 SHA·Worker·공개 manifest·공개 바이트 검증은 유지한다. 단계별 실제 시간은 CI artifact의 `build-timings.json`을 확인한다. 공식 생성기가 검토 산출물에 기록한 비공개 `data/.housing-validation.json`도 재사용한다. 검사 코드와 현재 manifest·참조 파일·상세 조각의 모든 바이트 해시가 일치해야 한다. 기록이 없거나 유효하지 않으면 전체 의미 검사 또는 기존 PASS 캐시 검사를 수행한다. 이 기록은 공개 자산에 포함하지 않는다.


- `main` push → Cloudflare Production: 운영 환경 검사 → 타입·기능·자산 검사 → Worker/정적 자산 배포 → 같은 SHA·manifest·공개 파일 해시·없는 JSON 404 확인 → Google 로그인 시작 확인.
- `cloudflare-staging` push → Cloudflare Staging: 시험 DB와 Worker만 사용한다. 운영 활성화 여부는 시험 대상 검사의 조건이 아니다.
- 운영 배포는 일반 DB migration, 데이터 초기화, secret 생성/교체를 하지 않는다. 현재 Production YAML에 명시된 승인된 board/member-library 테이블·키 검사는 고정된 대상과 검사 코드를 따르며, 기존 상태를 보존한다. 이 문서는 추가 스키마 승인이 아니다. 현재 D1과 기존 회원/관리자/세션을 보존한다. 스키마 변경은 별도 절차가 필요하다.
- 운영 `AUTH_ENABLED=true`, `MAINTENANCE=false`, `WITHDRAWAL_ENABLED=true`를 소스에 저장했다. 배포마다 임시 옵션으로 켜는 방식은 종료한다.
- Cloudflare Custom Domain과 www 리디렉션은 대시보드에서 관리한다. Wrangler `routes`/`route`는 지정하지 않는다. 설치된 Wrangler는 custom domain 목록이 비어 있으면 도메인 게시를 실행하지 않는다. 배포 후 실제 운영 도메인 접근으로 연결 보존을 검증한다. CI 토큰에 DNS·결제 권한을 추가하지 않는다.
- `tools/deployment-provider.json`과 저장소 변수 `NODESTREAM_DEPLOYMENT_PROVIDER`는 `cloudflare`다. 기존 Pages 완료 후 캐시 Purge 작업은 건너뛴다. GitHub Pages와 Supabase 자체는 아직 삭제하지 않는다.
- 무료 플랜 유지. 운영 환경은 `main`, 시험 환경은 `cloudflare-staging`만 허용한다. 수동 검토자·승인 대기 시간을 추가하지 않는다.
- 빈 DB·비공개 Worker를 전제로 했던 일회성 `cloudflare-prepare-production.yml`은 제거했다. Git 이력에서 확인 가능하며 공개 이후 재실행하지 않는다.
- 수집 일정과 공개 데이터는 이번 연결 작업에서 재생성하지 않는다. 생성기는 공통 provider 계약을 읽어 Cloudflare 공개 검증 경로를 사용해야 한다.
- 6시간 주기 Health는 별도 활성 변수로 켠다. 자동 비용 측정은 구현되어 있지 않으며 무료 플랜에 유료 가입이나 비용 차단을 추가하지 않는다.

운영 환경 변수: `CLOUDFLARE_PRODUCTION_ENABLED=true`, `CLOUDFLARE_PRODUCTION_AUTH_APPROVED=true`, `CLOUDFLARE_PRODUCTION_WRITES_APPROVED=true`, 기존 계정/D1 ID와 `CLOUDFLARE_WORKERS_PLAN=free`.

전월세는 사용자 결정(2026-10-03)에 따라 기존 원천별 대표가격·가중치·건수·지역 귀속을 유지한다. 승인된 공개 단지별 내부 캐시에는 소속 원천의 기여 자료를 함께 저장하되 집계할 때 원래 원천 순서를 복원한다. 공개 단지로 가격을 하나로 합치거나 지역 간 원천의 기존 집계 귀속을 변경하지 않는다. 매매는 기존 공개 단지 그룹 계산을 유지한다. 승인 연결 변경은 관련 묶음을 무효화하며 원천 번호·승인 자체는 변경하지 않는다.

지도 가격의 내부 캐시는 `cloudflare/dist/region-price-cache-v2`와 CI `region-prices-v2`를 사용한다. 해당 월의 실제 번호·정확 면적·공개 연결과 가격 입력이 같으면 기존 압축 결과를 재사용한다. 단지 추가·표시 정보 변경 때문에 모든 과거 가격 계산을 다시 하지 않는다. 입력이 바뀐 월은 그룹별 가격 증거를 대조하며 현재 월 파일 해시로 영향 받은 분기만 묶는다. 공개 경로·schema는 유지한다. 현재 입력의 해시를 확인하고 실행 중 변경되면 빌드를 차단한다.

전세·월세는 동일 지역·월의 해석한 상태를 공유한다. 해석한 상태는 한 달까지만 보관하며 전체 과거 자료를 메모리에 누적하지 않는다. 현재 물리 파일 해시는 실행 내 공유하고 종료 전에 다시 확인한다. 낮은 단계의 packed 분기 해석기는 4개 항목 상한을 유지하므로 최초 전체 구축에서는 퇴출된 물리 분기를 다시 해석할 수 있다. `rentalStateParses`는 지역·월 상태 읽기 횟수이며 물리 파일 전체 해석 횟수와 구분한다.

`build-timings.json`의 `regionPriceStats`에서 계산/재사용 그룹 수와 가격 재계산 없이 표시 정보만 갱신한 decoratedGroups, 월·분기 재사용과 무효화 원인(missing/inputs/engine/corrupt)을 확인한다. 처음 캐시를 구축한 비용과 이후 변경 입력의 빌드 시간을 별도로 보고한다. 그룹·월 증거는 공개 자산이나 Git에 넣지 않는다. 현재 내부 캐시는 약 2.17GB이며 공개 업로드와 별개다. CI 캐시 복원·저장 전송량과 시간도 전체 배포 시간에 포함해 관찰한다. 원천 오류를 캐시 손상처럼 처리하거나 전체 검사 모드를 우회하지 않는다.

### 복사본 성능 시험

`node tools/benchmark-region-prices.mjs --root FIXTURE --report NEW_JSON`으로 전체 가격 파일의 이번 시간·해시·재사용 수를 남긴다. `--reference`는 기존 모델 계산, `--compare REFERENCE_JSON`은 모든 공개 분기 압축 해시 비교다. 기존 보고서를 덮어쓰지 않는다.

`node tools/benchmark-region-price-changes.mjs --root FIXTURE --report NEW_JSON`은 `fixture.json`에 `isolated:true`인 공개 입력 복사본에서만 번호 추가·신규 거래·가격 정정과 기존 모델의 변경 분기 비교를 수행한다. 운영 사이트·DB 루트는 거부한다. 시험 데이터는 finally에서 복원하지만 프로세스가 강제 종료되면 해당 시험 복사본을 보존하고 조사한다. 시험 캐시·합성 거래를 운영으로 복사하거나 공개하지 않는다. 큰 JSON 보고서·로그는 전체를 터미널에 출력하지 않고 필요한 상태·시간·오류 필드만 읽는다. 한 줄 JSON 로그에 Get-Content -Tail을 사용하면 완료된 작업의 로그 표시만 오래 남을 수 있으므로 실제 result의 완료 상태와 프로세스를 따로 확인한다. `--months`를 사용한 수치는 해당 구간의 시험이며 전체 CI 시간으로 해석하지 않는다. 입력 복사와 최초 캐시 구축 비용은 변경 입력 계산 시간과 분리한다.

## 구현·검증 기록

최초 자동 배포 연결의 시험 `34747744688`, 운영 `34747848391`, Health `34747944425` 성공은 [2026-09-13 전환 기록](cloudflare-production-cutover-2026-09-13.md)에 보존한다. 현재 구현의 생성·검증 재사용과 실제 CI/공개 시간은 [워크플로우 실측](../../15_26/docs/workflow-redesign.md)을 따른다. 과거 실행 번호를 새 배포의 성공 증거로 재사용하지 않는다.

### 백업 재현 개선 중간 실측 (2026-10-02~03)

동일 공개 입력의 기존 지도 전체 계산은 3,756.139초, 첫 개선본의 전체 대조는 2,735.291초, 같은 입력 반복은 220.718초였다. 630개 공개 분기 압축 파일 해시가 모두 일치했다. 첫 개선본에는 전월세 공개 단지별 캐시 묶음이 아직 없으므로 이 수치를 최종본이나 실제 CI 시간으로 보고하지 않는다. 최종 묶음·상태 공유 구현의 최초 전체 구축은 4,668.278초(77분 48초)였으며 630개 공개 분기 압축 해시가 모두 일치했다. 최초 구축은 기준보다 느렸고 일부 이전 내부 증거를 다시 만들었다. 변경 입력·반복 실행 및 실제 CI 시간은 별도로 측정한다.

DB 백업 복사·복원을 제외한 전체 처리 기준은 1,650.956초, 최종본은 1,439.604초(12.80% 감소)이며 목표 20%에는 미달했다. 원본 감사·stage 생성·반영 전 검사·교체·장부·리뷰 후처리·최종 무결성을 포함했다. 지도 계산과 결과 대조가 동시에 실행되어 부하가 완전히 같지는 않았으며 수치를 임의 보정하지 않았다. 전체 거래 열·중복·승인·필지·판정·이력 대조는 차이 없이 통과했다. 시험 복사본은 운영 백업 성공이나 야간 관찰 횟수로 계산하지 않는다. 최종 운영·CI 결과는 운영 보고서에 따로 기록한다.
