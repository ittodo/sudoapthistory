# 공통 단지 자동완성

2026-09-20 로컬 구현 및 검증 기록. 운영 배포는 수행하지 않았다.

## 화면 동작

- 단지 후보는 `송파구 · 리센츠`처럼 시군구를 앞에 표시한다. 둘째 줄은 동 이름이며 같은 이름·시군구·동의 후보가 겹칠 때 주소를 추가한다.
- 매매·전세·월세의 단지 검색, 지도, 실거래, 기간별 실거래, 통계, 비교 및 기존 단지/계약 목록에 같은 모듈을 연결했다. 단지 입력창이 없는 화면에는 검색창을 새로 만들지 않았다.
- 지역·시군구 범위의 전체 단지에서 최대 10개를 추천한다. 거래 기간·금액·면적 조건은 후보를 선택한 뒤 기존 본문 조회에 적용한다. 본문 정렬과 자유 입력, 평형 검색은 유지한다.
- 단지를 고르면 `searchApt`에 공통 식별자를 저장하고, 각 화면은 확인된 원천 식별자로 거래를 좁힌다. 비교 화면에서는 해당 단지의 평형 목록으로 좁힌 뒤 기존 평형 선택을 이어간다.
- 새로고침·공유·뒤로 가기·거래 유형 전환에서 선택을 복원한다. 입력 수정·초기화는 선택을 해제하고, 지역 범위를 벗어나는 선택은 해제 안내를 표시한다.
- 조건에 맞는 거래가 없으면 “단지는 있으나 현재 조회 조건에 맞는 거래가 없습니다”를 표시한다.
- 한글 조합 중에는 검색하지 않는다. 조합 완료/입력 후 150ms 지연, 이전 응답 무시, 방향키·Enter·Escape, 터치, combobox/listbox 및 실시간 안내를 지원한다. 첫 후보는 Enter만으로 자동 선택하지 않는다.
- 자료를 불러오지 못해도 기존 본문 검색을 사용할 수 있고 자동완성 재시도를 제공한다.

## 자료와 검색 규칙

`tools/build-search-data.mjs`가 빌드/로컬 서버 시작 시 아래 자료를 합쳐 `/data/search/apartments.json`을 생성한다. 거래 내역 파일은 검색 자료 생성이나 검색 Worker에서 읽지 않는다.

- `data/index.json`: 평형 행과 원천 식별자
- `data/apartments/index.json`: 기존 승인된 식별자 연결과 모호한 연결 목록
- `data/daily/catalog.bin`, `data/rental/catalog.bin`: 매매·전월세 단지 카탈로그
- `data/map/index.json`: 지도 식별자와 좌표
- `data/housing-v3/index.json`: 승인된 단지 메타데이터

연결이 확인된 식별자로만 합치고 이름이나 좌표 유사도로 합치지 않는다. 연결 미확정 전월세 단지는 `rental:<원천 ID>`로 유지한다. 등록된 이름 변형은 별칭에 보존한다. 숫자 시군구 코드는 기존 전월세 모델의 이름 변환을 재사용한다.

현재 20,929개 단지이며 이 중 전월세 전용 1,718개와 거래 카탈로그에 없는 메타데이터 단지 44개를 포함한다. 원본 6개의 SHA-256, 자료 버전, 결과 JSON과 Worker의 해시를 배포 산출물 검증에 포함한다. 원본이 포장 도중 바뀌면 빌드가 실패한다.

자료 버전: `ed3ff04ed6e96b6da0f046970b3b31bf3a46b22e965e2daf09b5d5cb42ad9377`.

[es-hangul](https://github.com/toss/es-hangul) **2.4.0**을 정확한 버전으로 고정했다. 초성 추출과 자모 분해에 사용하며, 순위 계산은 `js/apartment-search-model.js`에 있다. MIT 라이선스와 라이브러리를 Worker 번들에 포함해 자체 제공한다.

정확 일치 → 앞부분 일치 → 부분 일치 → 초성/입력 중 자모 → 가벼운 오타 순서로 정렬한다. NFKC·대소문자·공백·괄호 차이를 정리하되 숫자와 괄호 안 단어는 남긴다. 여러 단어는 모두 이름/별칭 또는 지역/주소와 맞아야 하며 지역에는 오타를 허용하지 않는다. 이름 오타는 한글 세 음절 이상, 자모 편집거리 비율 0.25 이하로 제한한다. 명시한 단지·차수 번호가 다른 후보는 제외한다. 동순위는 거리·길이 차이·이름·주소·식별자로 안정 정렬하며 백분율 점수를 표시하지 않는다.

문서당 Worker 하나가 첫 검색 사용 시 목록을 한 번 받고 색인을 재사용한다. 지역별 후보를 먼저 좁힌다. 식별자가 있는 URL을 복원할 때도 동일한 목록을 사용한다.

- 390×844 화면에서 후보창과 문서의 가로 넘침이 없었다. 세로 스크롤바가 있는 경우에도 후보창을 문서의 실제 표시 폭 안에 맞춘다.

## 성능 측정

환경: Windows 10.0.26200, AMD Ryzen 7 6800H, 논리 코어 16개, Node 22.18.0. 2026-09-20 측정. 전체 단지 20,929개, JSON 6,080,985바이트, 자체 제공 Worker 11,730바이트.

`npm run bench:search`는 별도 Node Worker에서 실제 전체 목록으로 14종 입력을 준비 후 8회씩, 총 112회 측정한다.

| 항목 | 측정값 |
| --- | ---: |
| JSON 해석과 색인 준비 | 285.35ms |
| 색인 준비 후 추가 JS heap | 36.35MiB |
| 검색 중앙값 | 24.24ms |
| 검색 상위 95% | 46.27ms |
| 검색 최댓값 | 57.14ms |

브라우저는 입력 지연 150ms를 제외하고 Worker 요청부터 결과 반영 후 두 번의 animation frame까지 측정했다. 인앱 브라우저, 동일 PC에서 준비된 색인을 사용한 표본이다.

| 화면 크기 | 입력 | Worker 검색 | 결과 표시 |
| --- | --- | ---: | ---: |
| 1440×1000 | `리센ㅊ` | 20.00ms | 42.70ms |
| 1440×1000 | `잠실 리센트` | 31.30ms | 60.60ms |
| 390×844 | `반포` | 13.90ms | 29.70ms |

표본에서 데스크톱 100ms 목표를 충족했다. 390px 측정은 PC에서 모바일 화면 폭을 적용한 결과로, 실제 모바일 기기의 200ms 목표와 메모리 사용량은 별도 기기 검증이 필요하다. 최초 목록 다운로드 시간은 위 준비 후 검색 시간에 포함하지 않는다. heap 값도 브라우저 전체 메모리가 아닌 Node Worker의 색인 추가 사용량이다.

## 홈 단지·평형 목록과 최신 가격 요약 (2026-09-22)

홈의 매매·전세·월세는 기존 스크리너의 표, 모바일 카드, 검색, 정렬, 페이지 이동과 평형 통합을 함께 사용한다. 날짜별 계약 통계는 실거래·통계 화면에 남긴다. 원본 매매 행 번호와 계산 지표는 유지하며 승인된 공통 검색 카탈로그로 전월세 전용 평형을 추가한다. 이름·좌표로 연결하지 않는다. 거래가 없는 유형은 ‘거래 없음’으로 표시하고 정렬 마지막에 둔다. 전월세 전용이라는 이유로 임대 단지로 분류하지 않는다.

`build-search-data.mjs`의 기존 자산 포장 단계가 `build-home-search-data.mjs`를 호출한다. 이미 생성된 최신 전월세 상태 스냅샷의 opening/updates를 접어 최신 유효 계약을 고르고, 기존 rental-model의 해제 제외·환산 계산을 재사용한다. 단지·반올림 평형·유형별 최신 계약일, 동률 시 원천 거래 ID 순서를 사용한다. 실제 계약 면적과 원천 ID도 보존한다. 환산율이 없으면 원금액만 표시한다.

- `data/search/latest-{41,11,28}.bin`: 지역별 공통 카탈로그와 최신 전세·월세 계약 요약.
- `data/search/latest-index.json`: 자료 기준일, 공통 검색/전월세 버전, 입력 파일 및 요약 파일 SHA-256.
- 브라우저는 요약과 동일 입력 해시의 매매 인덱스를 검증하고 기존 공용 검증 캐시에 저장한다. 문서 내 동시 호출과 탭 전환은 같은 Promise/자료를 재사용한다. 홈에서는 과거 월 파일이나 전체 계약 이력을 받지 않는다. 상세를 열 때만 기존 이력 조회를 사용한다.
- 지역·동·단지·면적·세대수·준공연도는 공통이고 가격 범위·정렬은 유형별 URL/로컬 상태에 보관한다. 지도에서 저장한 과거 날짜는 홈 조회에 사용하지 않는다. 전월세에는 매매 투자지표 필터를 적용하지 않는다.
- 상세는 기존 패널/모바일 상세를 연다. 연결 미확정 ID는 공통 카탈로그의 정확한 원천 ID만 사용해 같은 상세의 전월세 이력을 조회한다. 다른 단지로 대체하지 않는다.

실제 자료에서 원본 41,342행을 유지한 공통 목록은 과거 단지 포함 61,456행이다. 기본 과거 단지 제외 목록은 61,416행이다. 요약 포장 표본은 약 3.9초, 지역 파일 합계 약 5.57MB(압축)였다. 원장 재생성 시간이나 모바일 네트워크 시간은 포함하지 않는다. 산출물은 기존 배포 manifest에 포함되며 원본 DB·승인 연결·필지는 수정하지 않는다.

## 로컬 실행

`npm ci` 후 `npm run preview`로 실행한다. 기본 주소는 `http://127.0.0.1:8793`이다. 검색 모델 또는 원본 자료를 변경하면 로컬 서버를 다시 시작해 생성된 자료와 Worker를 갱신한다. 운영 산출물은 `npm run build`로 생성되며 이 작업만으로 운영 배포되지는 않는다.

## 예약 배포 호환

운영/시험 배포 모두 `test:search`를 실행한다. 실제 카탈로그 검사는 고정된 단지 수를 전제하지 않고 해당 빌드의 매매·전월세 원천 전체가 포함되는지 대조한다. 수집으로 단지가 추가되거나 승인된 연결이 바뀌어도 최신 원본으로 검색 목록을 다시 생성한다. 생성된 JSON과 Worker는 `cloudflare/dist/public` 아래에만 저장하며 Git 작업 트리를 변경하지 않는다. 별도의 검색 자료 생성 예약은 필요 없다.
