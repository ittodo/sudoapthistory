# 회원 운영: 탈퇴·연령 확인·보관함·이용 통계

> 문서 역할: **기능·구현 설명** · [문서 목록](README.md)
> 현재 운영·공개 자료 계약은 문서 목록의 기준 문서를 따릅니다. 날짜·건수·성능 수치는 해당 검증 조건의 기록입니다.


2026-09-13 · 승인된 정책 · 로컬/시험 검증과 실제 Google 연결 해제·복구 사용자 검증 완료. 운영 초기 이력 정합화·전용 키·스키마 2·새 Worker 비공개 배포 완료. 이 문구는 운영 공개 로그인/도메인 전환 전의 기록이다. 이후 공개 전환은 [운영 자동 배포](cloudflare-auto-deployment.md)와 Git 이력을 따른다.
미배포 즉시 삭제 설계를 대체한다. 이미 영구 삭제한 자료는 복구하지 않는다.
Supabase 데이터 이관·회원 매핑·정방향/역방향 이관·Google 프로젝트 분리·DNS 변경은 범위 밖이다.

## 이용자 흐름

동일 Google 계정 확인 → 최종 확인 → 계정 사용 중지와 전체 사이트 세션 폐기 → Google 권한 철회 1회 시도.
사이트만 탈퇴하는 선택은 없다. Google 계정 자체를 삭제하는 기능이 아니다.

> 탈퇴 후 30일 동안 계정 정보를 복구 목적으로 보관합니다. 이 기간 안에 같은 Google 계정으로 인증하고 탈퇴 취소를 확인하면 기존 닉네임·댓글·추천·태그 투표가 복구됩니다. 30일이 지나면 복구할 수 없으며, 다시 가입해도 새 회원으로 시작합니다.

마감은 서버 탈퇴 시각 + 2,592,000초이며 한국 시간으로 표시한다. 마감과 같은 시각부터 복구 불가다.
동일 Google sub로 인증하면 일반 세션 대신 10분 유효한 복구 전용 일회성 쿠키를 발급한다.
인증만으로 복구하지 않고 ‘탈퇴 취소 및 계정 복구’를 명시적으로 확인해야 한다.
취소하면 탈퇴 상태를 유지한다. 재인증 중 새 Google 동의가 남을 수 있음을 안내한다.
확인 도중 마감이 지나면 거부하며 자동 신규 가입으로 바꾸지 않는다.
마감 이후 별도의 정상 로그인에서는 새 내부 회원 ID를 생성한다. 이메일로 계정을 합치지 않는다.

## 보관·공개·복구

- `active → withdrawn → purging` 상태, 탈퇴 시각·마감·회차를 저장한다. 탈퇴 대기 계정은 로그인과 쓰기가 차단된다.
- 회원 ID와 닉네임을 예약한다. 본인 댓글 본문·작성자는 숨기고 타인 답글은 보존한다. 필요한 부모 위치에 ‘탈퇴한 회원의 댓글입니다.’를 표시한다.
- 본인 추천·태그 투표는 보관하되 공개 집계에서 제외한다. 복구하면 남아 있는 유효한 대상/회원에 대해서만 다시 반영한다.
- 공유 태그·종목 연결은 공개 유지하되 생성자 연결은 비공개다.
- 직접 삭제한 댓글은 복구하지 않는다. 관리자 숨김과 그 30일 만료도 유지한다. 탈퇴 상태를 댓글 삭제/숨김 필드에 덮어쓰지 않는다.
- 복구는 복사나 DB 되감기가 아닌 동일 회원 상태 전환이다. 새 세션을 발급하고 관리자 역할은 별도 재지정한다.
- 재탈퇴 시 회차와 마감을 새로 계산한다. 대기 중 중복 요청으로 기간을 연장하지 않는다.

## API·경쟁 제어

`POST /api/account/withdrawal/start`, `confirm`, `cancel`과 `GET /api/account/withdrawal/status`를 사용한다.
기존 `DELETE /api/account`도 동일 확인 절차를 거쳐 즉시 삭제 우회를 차단한다.
OAuth는 oauth4webapi·PKCE·state·nonce·JWT 검증을 유지하며 재확인 sub가 세션 회원과 일치해야 한다.
`GET /api/account/recovery`는 가능 여부·마감·복구용 CSRF만 반환한다.
`POST /api/account/recovery/confirm`은 전용 쿠키·Origin·CSRF 및 회원 ID·회차·마감·미사용 자격을 D1 batch에서 원자적으로 확인한다.
`POST /api/account/recovery/cancel`은 복구 자격만 폐기한다. 일반 세션 없이 결과 확인/복구가 가능하다.
정리와 복구는 조건부 상태 변경으로 한쪽만 성공한다. 쓰기 SQL도 active 상태를 재확인한다.

## Google 철회와 실패

접근 토큰은 탈퇴 본인 확인 후 최대 10분간 AES-256-GCM으로 암호화하며 환경/요청 ID를 인증 데이터에 결합한다.
시험·운영별 `WITHDRAWAL_ENCRYPTION_KEY`(32바이트, 64자리 hex)를 Worker secret으로 분리한다. Google client secret을 재사용하지 않는다.
키·토큰은 Git/응답/로그/브라우저 저장소에 출력하지 않는다. 확정 처리에서 DB 토큰을 제거하고 메모리 토큰으로 철회를 시도한다.
DB 상태 변경 실패 시 철회하지 않는다. Google HTTP 200만 성공으로 기록하고 오류·5초 timeout·중단은 성공으로 추정하지 않는다.
계정 중지와 Google 결과를 별도로 저장/표시한다. 미확인 시 ‘Google 연결 해제 미확인—전체 처리 미완료’와 연결 관리 링크를 제공한다.
결과 쿠키는 최대 10분이며 재로그인할 필요가 없다. 지연 자동 재시도는 나중에 재동의한 권한을 철회할 수 있어 하지 않는다.
동일 프로젝트의 기존·시험·운영 Google 권한에 영향이 있을 수 있으나 다른 환경 회원 DB는 삭제하지 않는다.

## 만료 정리·스키마

`0002_withdrawal_requests.sql`은 스키마 2, 회원 상태, 탈퇴 요청, 복구 자격과 관련 인덱스를 추가한다.
만료 계정 최대 20개를 purging으로 전환하고 실 Google 식별자·이메일·닉네임 예약을 해제한다.
기존 NOT NULL/UNIQUE 제약을 유지하려고 정리 중 Google 식별자에는 원본 대신 `purged:<내부 ID>`를 사용한다.
시간당 최대 5개 계정을 순차 처리하며 각 데이터 종류는 최대 500행씩 제거한다. 수신 추천이 남은 댓글은 다음 실행에서 찾도록 연결을 보존한다.
타인 답글과 생성자 없는 공유 태그는 남긴다. 중단 후 안전하게 이어가며 정리 지연으로 복구 기간을 연장하지 않는다.
로그인/닉네임 사용 경로도 해당 만료 계정의 예약을 즉시 해제한다.
수동 백업은 만들지 않는다. D1 기본 복구 이력 잔존은 회원 복구와 별개이며 자동 되감기는 하지 않는다.

## 배포 및 확인 순서

1. 가상 DB/Google로 권한·경계·닉네임·중복·복구·정리 재시도·본문 보존·철회 성공/실패/timeout/DB 실패 검증. 실제 회원 날짜 조작 금지.
2. 시험 전용 키 등록 후 스키마 2와 Worker 시험 배포. 기존 키 덮어쓰기 금지.
3. 전용 실제 계정으로 탈퇴 → Google 연결 관리 확인 → 재인증 → 명시적 복구를 사용자와 검증. HTTP 200만으로 Google 연결 UI 제거를 단정하지 않는다.
4. 운영의 수동 초기 스키마를 0001과 비교하고 migration 이력을 정합화. 기존 DB에 0001 재실행 금지.
5. 개인정보 초안의 운영자/시행일/법적 미확정 사항 확정 후 운영 키·스키마·배포 절차 진행.
6. 탈퇴 상태를 무시하는 스키마 1 Worker로 복구 금지. 같은 D1과 탈퇴 차단을 지원하는 호환 버전만 사용한다.

## 만 14세 이상 자기확인

Google 로그인 전에 체크되지 않은 필수 확인란을 표시한다. 생년월일을 수집하거나 실제 연령을 인증하지 않으며 거짓 선택을 막을 수는 없다.

- 일반 `/auth/google` GET은 확인 화면을 반환한다. POST는 동일 출처, 단기 보안 쿠키와 CSRF 값, 단일 `age14=yes`를 검사한다.
- 확인한 OAuth 요청의 서버 보관 nonce에 버전 접두사를 포함하고 callback에서도 확인 여부를 검사해 미확인 신규 회원 생성을 막는다.
- 사용자별 연령 정보나 DB migration은 두지 않는다. 일반 로그인마다 다시 확인하며 기존 세션은 종료하지 않는다.
- 기존 세션에 연결된 탈퇴 본인 재확인은 예외다. 세션과 동일 Google 계정 검사는 유지한다. 탈퇴 대기 계정의 일반 로그인은 확인 후 명시적 복구 흐름을 따른다.
- 확인 화면 form-action에는 정확한 `https://accounts.google.com`만 추가해 제출 후 Google 이동을 허용한다. 동일 출처·CSRF 검사는 유지하고 JSON 응답에 UTF-8 charset을 명시한다. `/auth/google`의 GET 200 확인 화면만 `Referrer-Policy: same-origin`을 쓰며 Google 이동·callback은 `no-referrer`다. null·빈 값·외부 Origin 허용 예외는 두지 않는다.
- 배포 확인기는 확인 화면을 검증하고 명시적으로 제출한 뒤 Google 이동 주소까지만 점검한다. 실제 Google 로그인이나 회원 생성은 하지 않는다. 자동 HTTP 검증은 실제 모바일 브라우저 상호작용 시험을 대체하지 않는다.
- 개인정보 처리방침 초안에 자기신고 한계와 확인용 쿠키를 반영한다.

검증은 미체크·위조 출처·쿠키 누락·과대 본문·미확인 callback 차단, 체크 후 OAuth 시작, 기존 가입·탈퇴·복구·권한 시험이다.

## 회원 보관함과 단지 이용 통계

**범위.** 관심 단지·선택 지역, 회원·단지당 공개 하트 1개, 지역 순위, 거래→계산기 이동과 매수가 조정, 최근·저장 계산과 비교, 본인 활동, 익명 관리자 통계. 검색 프리셋·메모/폴더·종목 북마크·알림은 범위 밖이다.

**저장·API.** `0004_member_library.sql`이 관심 단지·지역·계산·원시 이벤트·일별 집계를 추가한다. 기존 계정·댓글 식별은 바뀌지 않는다. 사용자 자료는 비공개이며 최종 계정 삭제 시 함께 지워지고 탈퇴 계정은 하트에서 즉시 제외한다.

- `/api/me/favorites`, `/api/me/calculations`, `/api/me/activity`는 활성 세션이 필요하다. 쓰기는 동일 출처·CSRF·속도 제한을 따르며 낙관적 버전으로 오래된 변경을 거부한다. 관심 단지와 이름 붙인 계산은 회원당 200개 상한이다. 지역은 하트를 추가하지 않는다.
- `/api/apartments/hearts`는 ID 100개까지, `/api/apartments/ranking`은 시도·시군구 필터와 50행 페이지·동순위를 지원한다. 공개 요약은 승인된 원천 식별에서 만들며 취소·누락 거래를 제외한다.
- 계산 결과는 비공개 버전 입력·결과 스냅샷이다. 최근 슬롯은 계산 종류별이며 이름 저장은 원 거래·조건·결과를 보존하고 복원은 조용히 다시 계산하지 않는다. 같은 종류 2~3개를 비교한다.
- `/api/comments/focus`는 기존 가시성 검사를 쓰며 선택 댓글과 루트를 반환한다. 본인 활동은 중재를 우회하지 않는다.
- 관심 단지 요약과 관리자 댓글 라벨은 `js/apartment-records.mjs`의 `apartmentSummary(id)`를 쓴다. Worker의 관심 쓰기와 단지 이벤트도 같은 요약 판독기로 공개 단지 ID·선택 면적을 확인하며 전국 단지 카탈로그나 상세 거래 파일을 읽지 않는다. 파일 내용과 생성 규칙은 [단지 자료 계약](apartment-and-board.md#단지-정보와-호환-url)을 따른다. 구형 `apt_<row>` 댓글 경로만 전국 JSON 색인으로 행 ID를 해석하며 활동 화면은 결과에 단지 댓글이 있을 때만 그 색인을 읽는다.

**익명 단지 통계.** `/api/apartments/events`는 조회·하트·거래·계산기 이벤트를 받는다. 동일 출처와 공개 단지·면적을 확인하고 30분 HttpOnly 자체 방문 쿠키의 해시만 저장한다. 계정 ID·이메일·원시 IP·전체 리퍼러는 저장하지 않는다. 30분 안의 같은 단지·면적·종류 반복은 중복 제거하며 같은 세션의 선행 조회가 없는 행동은 버린다. 출처는 그날 첫 단지 조회에 귀속한다. 한국 시간 일별 집계는 이벤트와 원자적으로 갱신한다. `/api/admin/apartment-analytics`는 관리자 전용이고 여러 날 세션 합계는 일별 합이다. 시간당 정기 작업이 30일 지난 원시 이벤트를 지우되 일별 합계는 유지한다. 이 통계는 과금·고유 인원 지표가 아니다.

**배포.** 운영 workflow는 검토된 추가형 SQL만 고정 해시·고정 운영 대상으로 검증하고 기존 `sqlite_master` 정의를 확인한다. 중단된 마이그레이션은 테이블을 삭제·재생성하지 않고 이어 간다. 게시판 마이그레이션 단계는 별개다. 같은 커밋을 먼저 시험에 올린 뒤 테스트와 공개 자산 검사를 통과하면 운영에 배포한다. 실패 시 코드만 롤백하고 회원 자료를 복원·되감지 않는다. 검증은 API 격리·중재·탈퇴 삭제·재시도·충돌·집계 중복 제거와 보존·마이그레이션 중단·비호환 스키마 거부·계산기 0원금/0금리와 매수가 조정을 포함한다. 브라우저 시험은 임시 로컬 계정만 쓰고 실제 운영 금융 기록은 쓰지 않는다.

## 페이지 이용 통계

운영센터 `/admin/?view=pages`에서 오늘·최근 7일·30일(기본 7일)의 페이지 조회수를 본다. 날짜는 한국 시간이며 오늘을 포함한다. 단지 상세 패널도 페이지 조회에 포함한다. 로드·새로고침·뒤로 가기 복원마다 집계하고 같은 문서의 검색 조건·탭 변경은 집계하지 않는다. 단지 이용 통계는 별도다.

- `POST /api/analytics/pageviews`는 `{path,eventId,sentAt}`을 받는다. path는 허용된 정적 페이지 경로, eventId는 조회마다 만든 UUID v4, sentAt은 Unix 초다. 동일 출처만 허용하며 쿠키·방문자 ID·쿼리 문자열·IP는 저장하지 않는다. 같은 이벤트는 한 번만 집계한다. 전송 시각은 과거 24시간·미래 5분을 허용하고 집계 날짜는 서버 수신 시각 기준이다. 중복 방지 ID는 2일 뒤 정기 작업이 지우고 일별 합계는 유지한다. 자동화 요청을 완벽히 구분하는 방문자 지표가 아니다.
- `GET /api/admin/page-analytics?days=7`은 관리자에게 `{days,from,to,total,data:[{path,name,views}]}`를 반환한다. 허용 기간은 1·7·30일이며 기록이 없으면 빈 배열과 합계 0이다. 새 페이지를 추가하면 서버 pages 목록과 HTML 공통 스크립트를 함께 추가한다.
- 배포: `npm run typecheck`, `npm run test:api`, `npm run test:site`, `node --test tools/test-cloudflare-page-analytics.mjs`, `npm run build` 후 시험 D1에 `0006_page_analytics.sql`까지 적용하고 Worker와 정적 파일을 함께 배포한다. 운영은 검토된 0006 SQL의 해시·운영 DB 대상·기존 마이그레이션을 확인한 뒤 새 집계 테이블과 인덱스만 추가하고 확인 뒤 배포한다. 롤백해도 추가 테이블은 남긴다. 이전 조회수는 소급하지 않으며 스크립트 차단·네트워크 실패 시 누락될 수 있다.

**GA4.** 공통 `js/page-analytics.js`가 `G-4SPGCJTJJP`를 연결한다. HTTPS `nodostream.com`·`www.nodostream.com`의 최상위 문서에서만 Google 태그를 비동기 로드한다. 로컬·미리보기·관리자·인증·API 경로와 iframe 단지 패널은 제외한다. 태그의 `config`가 최초 조회를 한 번 보내며 수동 `page_view`를 중복 전송하지 않는다. 페이지 URL은 경로와 UTM 캠페인 파라미터만 남기고 쿼리의 검색·계산 입력과 해시를 제거하며 최초 리퍼러도 쿼리·해시를 제외한다. 계정 ID·이메일은 전달하지 않고 Google Signals와 광고 개인 최적화를 코드에서 끈다. GA4는 쿠키 식별자를 쓰며 자체 집계와 조회수가 일치하지 않을 수 있다.

GA4 관리 화면에서 확인할 서버 설정: 보고 시간대 대한민국과 웹 스트림 URL `https://nodostream.com`, 향상된 측정의 페이지 조회 고급 설정에서 **브라우저 방문 기록 이벤트 기반 페이지 변경** 끄기(검색·탭·패널의 `pushState`/`replaceState`를 별도 조회로 세지 않기 위함), 방문 집계 범위를 제한하려면 사이트 검색·양식 상호작용 등 불필요한 향상된 측정 끄기. 배포 후 실시간 보고서와 DebugView로 최초 조회와 이동을 확인한다. 로컬 시험은 Google로 요청하지 않으며 자동 시험은 초기화 큐·태그 삽입·호스트 제한·iframe 제외·자체 집계 보존만 검증한다. 공식 문서: https://developers.google.com/analytics/devguides/collection/ga4/views
