# 회원 탈퇴 30일 유예·복구

2026-09-13 · 승인된 정책 · 로컬/시험 검증과 실제 Google 연결 해제·복구 사용자 검증 완료. 운영 초기 이력 정합화·전용 키·스키마 2·새 Worker 비공개 배포 완료. 운영 공개 로그인/도메인 전환 전.
미배포 즉시 삭제 설계를 대체한다. 이미 영구 삭제한 자료는 복구하지 않는다.
Supabase 데이터 이관·회원 매핑·정방향/역방향 이관·Google 프로젝트 분리·DNS 변경은 범위 밖이다.

## 이용자 흐름

동일 Google 계정 확인 → 최종 확인 → 계정 사용 중지와 전체 사이트 세션 폐기 → Google 권한 철회 1회 시도.
사이트만 탈퇴하는 선택은 없다. Google 계정 자체를 삭제하는 기능이 아니다.

> 탈퇴 후 30일 동안 계정 정보를 복구 목적으로 보관합니다. 이 기간 안에 같은 Google 계정으로 인증하고 탈퇴 취소를 확인하면 기존 닉네임·댓글·추천·태그 투표가 복구됩니다. 30일이 지나면 복구할 수 없으며, 다시 가입해도 새 회원으로 시작합니다.

마감은 서버 탈퇴 시각 + 2,592,000초이며 한국 시간으로 표시한다. 마감과 같은 시각부터 복구 불가다.
동일 Google sub로 인증하면 일반 세션 대신 10분 유효한 복구 전용 일회성 쿠키를 발급한다.
인증만으로 복구하지 않고 ‘탈퇴 취소 및 계정 복구’를 명시적으로 확인해야 한다.
취소하면 탈퇴 상태를 유지한다. 재인증 중 새 Google 동의가 남을 수 있음을 안내한다.
확인 도중 마감이 지나면 거부하며 자동 신규 가입으로 바꾸지 않는다.
마감 이후 별도의 정상 로그인에서는 새 내부 회원 ID를 생성한다. 이메일로 계정을 합치지 않는다.

## 보관·공개·복구

- `active → withdrawn → purging` 상태, 탈퇴 시각·마감·회차를 저장한다. 탈퇴 대기 계정은 로그인과 쓰기가 차단된다.
- 회원 ID와 닉네임을 예약한다. 본인 댓글 본문·작성자는 숨기고 타인 답글은 보존한다. 필요한 부모 위치에 ‘탈퇴한 회원의 댓글입니다.’를 표시한다.
- 본인 추천·태그 투표는 보관하되 공개 집계에서 제외한다. 복구하면 남아 있는 유효한 대상/회원에 대해서만 다시 반영한다.
- 공유 태그·종목 연결은 공개 유지하되 생성자 연결은 비공개다.
- 직접 삭제한 댓글은 복구하지 않는다. 관리자 숨김과 그 30일 만료도 유지한다. 탈퇴 상태를 댓글 삭제/숨김 필드에 덮어쓰지 않는다.
- 복구는 복사나 DB 되감기가 아닌 동일 회원 상태 전환이다. 새 세션을 발급하고 관리자 역할은 별도 재지정한다.
- 재탈퇴 시 회차와 마감을 새로 계산한다. 대기 중 중복 요청으로 기간을 연장하지 않는다.

## API·경쟁 제어

`POST /api/account/withdrawal/start`, `confirm`, `cancel`과 `GET /api/account/withdrawal/status`를 사용한다.
기존 `DELETE /api/account`도 동일 확인 절차를 거쳐 즉시 삭제 우회를 차단한다.
OAuth는 oauth4webapi·PKCE·state·nonce·JWT 검증을 유지하며 재확인 sub가 세션 회원과 일치해야 한다.
`GET /api/account/recovery`는 가능 여부·마감·복구용 CSRF만 반환한다.
`POST /api/account/recovery/confirm`은 전용 쿠키·Origin·CSRF 및 회원 ID·회차·마감·미사용 자격을 D1 batch에서 원자적으로 확인한다.
`POST /api/account/recovery/cancel`은 복구 자격만 폐기한다. 일반 세션 없이 결과 확인/복구가 가능하다.
정리와 복구는 조건부 상태 변경으로 한쪽만 성공한다. 쓰기 SQL도 active 상태를 재확인한다.

## Google 철회와 실패

접근 토큰은 탈퇴 본인 확인 후 최대 10분간 AES-256-GCM으로 암호화하며 환경/요청 ID를 인증 데이터에 결합한다.
시험·운영별 `WITHDRAWAL_ENCRYPTION_KEY`(32바이트, 64자리 hex)를 Worker secret으로 분리한다. Google client secret을 재사용하지 않는다.
키·토큰은 Git/응답/로그/브라우저 저장소에 출력하지 않는다. 확정 처리에서 DB 토큰을 제거하고 메모리 토큰으로 철회를 시도한다.
DB 상태 변경 실패 시 철회하지 않는다. Google HTTP 200만 성공으로 기록하고 오류·5초 timeout·중단은 성공으로 추정하지 않는다.
계정 중지와 Google 결과를 별도로 저장/표시한다. 미확인 시 ‘Google 연결 해제 미확인—전체 처리 미완료’와 연결 관리 링크를 제공한다.
결과 쿠키는 최대 10분이며 재로그인할 필요가 없다. 지연 자동 재시도는 나중에 재동의한 권한을 철회할 수 있어 하지 않는다.
동일 프로젝트의 기존·시험·운영 Google 권한에 영향이 있을 수 있으나 다른 환경 회원 DB는 삭제하지 않는다.

## 만료 정리·스키마

`0002_withdrawal_requests.sql`은 스키마 2, 회원 상태, 탈퇴 요청, 복구 자격과 관련 인덱스를 추가한다.
만료 계정 최대 20개를 purging으로 전환하고 실 Google 식별자·이메일·닉네임 예약을 해제한다.
기존 NOT NULL/UNIQUE 제약을 유지하려고 정리 중 Google 식별자에는 원본 대신 `purged:<내부 ID>`를 사용한다.
시간당 최대 5개 계정을 순차 처리하며 각 데이터 종류는 최대 500행씩 제거한다. 수신 추천이 남은 댓글은 다음 실행에서 찾도록 연결을 보존한다.
타인 답글과 생성자 없는 공유 태그는 남긴다. 중단 후 안전하게 이어가며 정리 지연으로 복구 기간을 연장하지 않는다.
로그인/닉네임 사용 경로도 해당 만료 계정의 예약을 즉시 해제한다.
수동 백업은 만들지 않는다. D1 기본 복구 이력 잔존은 회원 복구와 별개이며 자동 되감기는 하지 않는다.

## 배포 및 확인 순서

1. 가상 DB/Google로 권한·경계·닉네임·중복·복구·정리 재시도·본문 보존·철회 성공/실패/timeout/DB 실패 검증. 실제 회원 날짜 조작 금지.
2. 시험 전용 키 등록 후 스키마 2와 Worker 시험 배포. 기존 키 덮어쓰기 금지.
3. 전용 실제 계정으로 탈퇴 → Google 연결 관리 확인 → 재인증 → 명시적 복구를 사용자와 검증. HTTP 200만으로 Google 연결 UI 제거를 단정하지 않는다.
4. 운영의 수동 초기 스키마를 0001과 비교하고 migration 이력을 정합화. 기존 DB에 0001 재실행 금지.
5. 개인정보 초안의 운영자/시행일/법적 미확정 사항 확정 후 운영 키·스키마·배포 절차 진행.
6. 탈퇴 상태를 무시하는 스키마 1 Worker로 복구 금지. 같은 D1과 탈퇴 차단을 지원하는 호환 버전만 사용한다.
