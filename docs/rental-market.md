# 전월세 월간 시장 동향

> 문서 역할: **기능·구현 설명** · [문서 목록](README.md)
> 현재 운영·공개 자료 계약은 문서 목록의 기준 문서를 따릅니다. 날짜·건수·성능 수치는 해당 검증 조건의 기록입니다.


`/market/`의 전세·월세는 전용 화면과 worker를 사용한다. 매매와 Chart.js 생성기 및 기준월 표시를 공유하며, 다른 전월세 메뉴는 기존 rental-app을 유지한다.

## 실행 지침

- packed-region(schema 3) 운영 자료의 기본 시장 조회는 빌드에서 만든 월별 집계를 읽는다. 전체·시도·단일 시군구, 계약 구분, 두 환산 기준·평당가·가격대 전환에 과거 계약 내역을 다운로드하지 않는다.
- 기준월 계약 내역은 **계약 내역 보기**를 눌렀을 때 해당 월만 읽는다. 단지 검색·면적·금액 조건이나 여러 시군구를 함께 선택한 경우에는 정확한 중위값을 유지하기 위해 거래 자료를 읽어 계산한다.
- 원본 버전·입력 해시가 다른 집계를 사용하지 않는다. 오래된 집계 인덱스는 검증된 원본 경로로 전환하며, 승인된 집계 파일의 해시가 틀리면 오류와 재시도를 표시한다.
- CI는 비공개 `housing-cache.sqlite`의 임대 통계 scope를 보관한다. [공통 캐시 보관 기준](cloudflare-auto-deployment.md#앞으로-지킬-배포검증-규칙)을 따른다. 바뀐 월만 다시 계산하고 연도별 묶음을 갱신한다. 최초 캐시 구축과 이후 재사용 시간은 구분한다.
- 변경 검증은 `npm run test:market`, 기존 rental model/worker 회귀 검사를 사용한다. 공개 배포는 기존 공식 배포 절차로 수행한다.

## 계산

- 전세: 보증금. 월세 기본값: 월세 + 보증금 × 연 환산율(%) / 1200.
- 보증금 환산: 보증금 + 월세 × 1200 / 연 환산율(%).
- 원본 거래에 기록된 계약 월·지역별 환산율과 적용 월을 그대로 사용한다. 공식 환산율이 없는 거래는 건수에만 포함한다.
- 해제 거래는 파생 자료 생성 시 제외한다. 평균과 중위값은 필터를 통과한 개별 거래에서 계산한다. 평당가는 거래별 금액 × 3.305785 / 전용면적이다.
- 가격대는 총액 기준이며 경계값은 하위 구간에 포함한다. 평당가 모드에서도 분류와 금액 합계는 총액을 사용한다.
- 누적 막대의 환산 불가 구간을 포함한 합계는 전체 거래건수와 일치한다. 가격은 자료가 없으면 null로 두어 선을 연결하지 않는다.

## 자료와 캐시

schema 3에서는 `build-rental-market-cache.mjs`가 취소 거래를 제외하고 월·거래유형·계약구분별 전체/시도/시군구 집계를 만든다. 평균·합계·건수·정확한 중위값·평당가·가격대는 기존 계산 모델을 공유한다. 시군구 중위값을 평균해 전체 중위값으로 사용하는 방식은 허용하지 않는다.

월별 캐시는 계산 코드와 두 단계 입력 근거를 저장한다. 먼저 분기 파일 해시, 기존 번호표의 정확한 앞부분, 정규화한 지역 귀속을 비교한다. 끝에 추가된 번호만으로는 과거 월을 해석하지 않는다. 기존 번호가 바뀌거나 파일이 달라지면 해당 월을 읽는다. 그다음 실제 집계 입력인 면적·보증금·월세·계약 구분·환산율·시도·시군구를 비교한다. 행 순서와 중복 건수를 유지한다. 같은 분기의 매매 변경이나 층 변경으로 전월세 집계 값이 같으면 통계를 다시 계산하지 않는다. 가격·취소·삭제·지역 귀속 변경은 영향을 받은 월만 다시 집계한다.

월별 계산 결과는 비공개 캐시에 gzip JSON으로 유지한다. 계산 코드 지문 `codeHash`와 별도 입력 근거로 통계 재계산 여부를 결정한다. 공개 BIN 코덱과 생성된 스키마 지문은 별도 `packingHash`로 추적한다. 연간 포장 캐시는 이 지문, 각 월 결과의 해시, 시군구 귀속을 사용한다. 같은 결과면 연간 포장을 생략한다. 한 달의 통계가 바뀌면 그 달이 속한 연간 파일만 다시 포장한다. 코덱만 바뀌면 월 통계는 재사용하고 포장만 갱신한다.

물리 파일과 현재 메타데이터의 해시는 재사용 여부와 관계없이 확인한다. 공개 인덱스와 시군구 목록은 현재 자료로 갱신한다. `NODO_FULL_VERIFY=1`은 재사용하지 않는다. 이번 계산·포장 지문 분리의 최초 적용에서는 builder 해시 변경으로 기존 월 계산 캐시가 한 번 무효화된다. 이후 코덱 변경에 따른 재포장과 최초 계산 비용은 구분한다.

`rentalMarketStats`의 `decoded`는 읽은 월 수다. `semanticReused`는 읽은 뒤 집계 입력이 같아 재사용한 월 수다. `calculated`와 `reused`는 실제 계산·재사용 월 수다. `packedYears`와 `reusedYears`는 포장·재사용한 연간 파일 수다.

공개 파일은 `data/rental/market-cache/YYYY-summary.bin`과 `index.json`이다. 연도별 경계는 유지한다. 2011~2026 자료를 포장하면 연간 BIN 16개와 JSON 인덱스 1개가 된다. 인덱스는 `schema: 2`를 유지하고 `format: packed-records-v1`을 선언한다. 원본 버전·`inputs` 원본 해시·`sources` 출력 해시·시군구 이름·매매 시작 연도를 담는다.

연간 BIN은 gzip으로 압축한 `PGRCD001` 컨테이너다. PolyGen이 생성한 타입별 열 코덱으로 월 키와 집계 값을 저장한다. 숫자는 `f64`, 값 트리의 하위 범위는 상대 길이 `span`을 쓴다. 각 월 레코드는 기존 `{schema: 2, month, groups}` 의미를 유지한다. 개별 계약의 날짜·층·단지 ID는 넣지 않는다. 자료가 없는 달과 거래 0건을 구분한다.

Worker는 필요한 연간 파일을 다운로드하고 압축을 푼다. `openRecords(raw).get(month)`로 요청한 월만 객체로 복원한다. 나머지 월의 집계 객체를 미리 만들지 않는다. 연간 판독기와 조회 결과는 재사용한다. 이는 월별 HTTP 범위 요청이 아니므로 첫 요청에서는 해당 연간 파일 전체를 받는다.

집계 인덱스가 유효하면 단지 목록도 지연 조회한다. 계약 내역이나 상세 조건을 요청할 때 기존 공통 거래 파일과 단지 목록을 읽는다. `format`이 없는 기존 schema 2의 연간 gzip JSON과 schema 1/2 원천·compact 캐시도 읽는다. 다운로드 동시 한도 3개, 검증된 브라우저 디스크 캐시, 상세 조회의 진행 중 요청 공유와 재시도 정책은 유지한다.

URL의 `marketRentMetric=monthly|deposit`은 시장 화면 전용이다. 기존 `from`, `to`, `m`, `mExact`, `r`, `gu`, `pm`, `tier` 해시를 유지한다. 전월세의 시작 연도와 관계없이 기존 `m`은 매매 시작 연도로부터 실제 연월로 바꾼다.

## 검증

- `npm run test:market`: 환산, 평당가, 중위값, 구간 경계, 필터 일관성, 링크 호환, 캐시 무결성·재사용·재시도. BIN/기존 JSON 결과 일치, 필요한 월만 복원, 연간 파일 경계, 한 달 변경의 영향 범위와 코덱 변경 시 계산 재사용도 확인한다.
- `node tools/test-rental-model.cjs` 및 `node tools/test-rental-worker.cjs`: 기존 전월세 회귀 검사.
- `npm run test:site`, `npm run build`: 기존 사이트 및 전체 패키징 검증.
- 로컬 미리보기에서 매매·전세·월세, 5개 지역 제한, 환산 토글, 가격대, 390px 화면, 빈 결과 및 URL 복원을 확인한다.

2026-10-23 로컬 검증에서는 `test:market` 28개 검사를 통과했다. 16개 연도의 32개월 시험 자료로 값 보존을 확인했다. 한 달 가격 변경은 해당 월 재계산과 연간 파일 하나의 변경으로 이어졌다. 코덱 변경은 월 통계를 재사용하고 연간 포장만 갱신했다. 운영 자료 전체 생성·배포의 완료를 뜻하지 않는다.

같은 날 전체 사이트 포장에서 만든 실제 16개 연간 BIN의 190개월을 월 계산 캐시와 전수 대조했다. 저장·복원한 모든 월 집계 값이 같았다. [일회성 대조 결과](../../_ops/reports/packed-transport-20261023/market-audit.json)는 형식 변환을 검산한 기록이다. 원천 통계 계산 자체를 새로 감사한 결과나 운영 배포 증명은 아니다.

## 과거 검증·측정: 연간 gzip JSON

이 절의 크기·시간·해시는 `PGRCD001` 전환 전 형식의 기록이다. 현재 BIN의 크기나 처리 성능으로 사용하지 않는다.

### 월 계산 캐시 측정 (2026-10-22)

운영 자료를 복사한 격리 입력으로 78개 지역의 2011-01, 2026-07~10을 비교했다. 이전 구현은 5개월을 6.562초에 계산했다. 수정본은 변경된 1개월을 계산하고 4개월을 재사용해 4.126초가 걸렸다. 같은 입력의 반복은 해석·계산 0개월, 1.843초였다. 당시 연도별 압축 결과 해시는 이전 구현과 모두 같았다. 최초 캐시 구축은 6.709초였다. 각 구간 1회 측정이며 전체 CI·배포 시간으로 환산하지 않는다. [실측 자료](../../_ops/reports/cache-scope-20261022/market-changed.json)를 보존했다.

### 구현·실측 근거 (2026-10-06)

- 시장동향 관련 23개 테스트, 기존 전월세 모델·worker 회귀 검사 통과. packed-region 입력으로 월별 캐시 재사용·메타데이터 변경 무효화·손상 차단도 검사했다.
- 저장된 2026-10 전월세 1,486건을 사용한 거래유형·계약구분·지역/시군구 40개 조건에서 기존 직접 계산과 정확히 일치했다. 테스트의 기본 집계 요청에는 계약 파일·단지 목록 다운로드가 0건이며, 계약 내역 요청에는 기준월 자료만 포함된다.
- 실제 190개월 최초 집계: 371.583초(6분 12초), 재사용 0개월. 동일 입력 반복: 14.387초, 재사용 190개월·재계산 0개월. 이는 집계 생성기 구간의 벽시계 시간이며 전체 CI·배포·브라우저 표시 시간과 다르다.
- 생성된 연도별 집계 16개와 인덱스 1개: 총 29,815,240바이트(약 28.4MiB). 기본 5년 조회는 선택 연도의 파일만 읽고, 개별 계약 자료는 상세 조회 때 받는다. 이 용량은 모든 계약구분·환산 기준·평당가·가격대 집계를 포함한다.
- 로컬 전체 빌드도 시작했으나 producer proof가 `INVALID`여서 기존 전체 자료 검사가 실행됐다. 매매 상세 185.489초·전월세 상세 37.647초 이후 다음 자료 검사 구간이 장시간 진행되어, 큰 비용 구간을 중단하고 별도 분석한다는 운영 원칙에 따라 이 작업이 시작한 빌드 프로세스만 중단했다. 전체 빌드 통과·공개 배포 완료로 간주하지 않는다. 공개 적용 전에 공식 빌드·배포 검증을 완료해야 한다.


### 배포 병목 점검 (2026-10-06)

직전 운영 SHA `be538aac2056f2b86555784052836f17734e1b45`의 CI 빌드 기록에서 지역 가격 생성은 1,802.139초, 전체 빌드는 1,817.071초였다. 공통 읽기 최적화 커밋을 함께 적용한다. 서울 2026-08·09 읽기 전용 비교에서 두 번째 달은 기존 1.3028초에서 캐시 사용 0.3579초로 줄었으며 전체 결과 SHA-256은 같았다. 이 구간 결과를 전체 CI 개선율로 해석하지 않는다.

전월세 요약 생성도 실행 범위의 용량 제한 해석 캐시와 종료 입력 재검사를 사용한다. CI build-timings.json에는 rentalMarketStats의 계산·재사용 월 수 및 산출 바이트를 기록한다. 공통 검사 코드 변경으로 기존 검증 증명이 무효가 되면 정식 검사를 다시 수행하며 기존 증명의 서명을 바꾸지 않는다.
