# Cloudflare 구현·검증 기록

기준일: 2026-09-13. 승인 범위는 [이전 계획](cloudflare-migration-plan.md),
실행 절차는 [배포 실행서](cloudflare-release-runbook.md)를 따른다.

## 외부 상태

### 시험 쓰기 활성화 준비

- 사용자가 시험 쓰기 활성화 배포 준비를 요청했다. 시험 설정만
  `MAINTENANCE=false`로 변경했다. 실제 적용은 GitHub 환경 승인과 배포 성공 후다.
- 사용자가 제공한 계정 화면에서 Google 로그인 후 세션 표시를 확인했다.
  신규 시험 회원이 있으므로 DB 초기화·되감기·시험 회원 삭제를 자동 실행하지 않는다.
- 운영 설정은 `MAINTENANCE=true`, `AUTH_ENABLED=false`를 유지하고 검사로 고정했다.
  기존 운영 사이트·DNS·요금제·수집 예약은 변경하지 않는다.
- 배포 후 닉네임·댓글·답글·추천·태그·로그아웃 기능을 시험한다.
  원격 권한·탈퇴·관리자 검사는 별도 시험 계정 준비 후 수행하며,
  사용자 계정을 탈퇴시키거나 관리자 권한을 자동 부여하지 않는다.
- 원격 기능 시험은 아직 미완료다. 로컬 가상 계정 시험과 구분한다.

### 2026-09-13 시험 Google 로그인 연결

- [Staging 실행 #2](https://github.com/ittodo/sudoapthistory/actions/runs/34717387572)는
  검사·배포·공개 검증·artifact 저장까지 성공했다.
- 사용자 승인으로 기존 Google `nodostream` 클라이언트에 시험 callback
  `https://nodostream-staging.sksk17.workers.dev/auth/callback`을 추가·저장했다.
  기존 Supabase callback은 유지했다.
- 별도 승인 후 Google client secret 하나를 추가하여 시험 Worker의
  `GOOGLE_CLIENT_SECRET` 암호화 Secret으로 저장·적용했다. 기존 키는 유지했다.
  새 키 원문은 Git·로컬 파일·채팅 출력에 기록하지 않았고 브라우저 임시 변수도 비웠다.
- 후속 진행 요청에 따라 공개 client ID와 `AUTH_ENABLED=true`를 시험 설정에만 반영했다.
  실제 활성화는 이 커밋의 GitHub 환경 승인 및 배포 성공 후다.
- `MAINTENANCE=true`는 유지한다. 현재 점검 모드는 프로필 변경·로그아웃·탈퇴를
  포함한 API 쓰기도 차단하므로 이번 단계는 신규 로그인과 세션 조회만 시험한다.
- 첫 로그인부터 시험 D1에 신규 회원·세션이 생성된다. DB 초기화나 자동 관리자
  지정은 하지 않는다. 운영 DB·도메인·요금제·운영 인증 활성화는 변경하지 않았다.
- 배포 후 로그인 시작 검사에서 Google 목적지·client ID·callback·PKCE·state·nonce·
  보안 쿠키를 확인한다. Google로 리디렉션을 따라가거나 사용자를 대신해 로그인하지 않는다.
  실제 동의 화면·코드 교환·회원 생성은 사용자 직접 로그인 후 별도 검증한다.

### 2026-09-13 첫 시험 배포와 공개 확인

- [Staging 실행 #1](https://github.com/ittodo/sudoapthistory/actions/runs/34716869968)의
  `ad539e7ef884a339aa7a2922e0839049cb04fdef`에서 D1 초기 스키마 적용과
  정적 파일 2,982개 업로드, Worker 배포가 성공했다.
- Worker 버전: `8b95ced7-d7c0-45c2-99eb-5ce3629c3b95`, DB schemaVersion: `1`.
- 배포 완료 직후 약 0.1초 만에 시작한 공개 검사는 `/deployment.json` 404로 실패했다.
  이후 같은 SHA·같은 로컬 manifest로 전체 공개 검사를 재실행해 성공했다.
  초기 공개 반영 지연으로 추정하며 파일 누락이나 토큰 권한 부족 증거는 없다.
- 실제 공개 검증 성공: Git SHA, Worker 버전, DB 스키마, manifest 해시,
  대표 HTML/JSON 바이트 해시 및 없는 JSON 404.
- CLI 공개 검증에 10초 간격 최대 7회, 전체 180초 제한을 추가했다.
  매 시도는 전체 검증을 다시 수행하며 지속적인 SHA/해시 불일치나 404는 실패한다.
- 기존 회원 데이터 이관·Google 로그인 활성화·운영 도메인/과금 변경은 하지 않았다.
  GitHub 실행 자체는 최초 검증 실패로 빨간 상태이며, 로컬 재검증 성공과 구분한다.

### 2026-09-13 무료 시험 배포 준비

- 운영 main 대신 `cloudflare-staging` 브랜치를 사용한다. 기존 Pages는 유지한다.
- 시험 브랜치 push → 자격증명 없는 검사 → GitHub 소유자 환경 승인 →
  고정된 staging 대상 검사 → 시험 스키마 적용 → Worker 배포 → 공개 해시 검증 순서다.
- 시험 URL 및 활성화 환경 변수를 등록했다. 승인 규칙과 토큰 권한은 변경하지 않았다.
- 시험 URL은 `https://nodostream-staging.sksk17.workers.dev`이며 실제 공개 확인 전이다.
- Google 로그인 비활성·점검 모드를 유지한다. 회원·댓글·태그 등 기존 데이터 복사는 없다.
- 원격 스키마·Worker 성공 여부는 실제 Actions 실행 결과로 별도 기록한다.

### 2026-09-13 배포 권한 연결 완료

사용자 승인 후 Cloudflare 토큰 `nodostream-staging-github-actions`를
생성하고 `ittodo/sudoapthistory`의 `cloudflare-staging` 환경에
`CLOUDFLARE_API_TOKEN` secret으로 저장했다. 같은 환경에
`CLOUDFLARE_ACCOUNT_ID` variable도 설정했다.

- 권한: 지정 계정의 Workers Scripts 편집·D1 편집 두 가지.
- DNS·결제·R2·계정 관리 권한 없음. 특정 시험 DB 하나로 제한되는 토큰은 아님.
- 만료일 미지정. 종료 시 폐기 또는 갱신 필요.
- GitHub 환경 사용에 소유자 `ittodo` 승인 필요, 관리자 우회 불가.
- 토큰 원문은 파일·Git·채팅 출력에 기록하지 않았고 임시 브라우저 작업 변수도 비웠다.
- UI에서 Cloudflare 토큰 활성 상태 및 GitHub secret 저장을 확인했다.
  실제 API 권한 행사·배포·원격 스키마 적용은 실행하지 않았다.
- 이 연결 단계에서는 시험 배포 활성화 설정·시험 URL이 미설정이었다. 이후 준비는 위 절을 따른다. 운영 도메인·과금·Google 설정은 그대로다.

### 초기 구현 당시 상태 (위 연결 완료 전)

운영 배포·DNS·Google 설정·Supabase·Cloudflare 과금·GitHub secrets·
실제 예약 작업은 변경하지 않았다. 기존 데이터를 내보내거나 복사하지
않았고 수집 DB를 백업·변경하지 않았다.

계획 범위에서 **무료 시험 D1 `nodostream-staging`을 새로 생성했다.**
식별자: `636d41b6-3ed7-4f6d-8f0b-823324c4ccad`.
생성 직후 관리 화면에서 테이블 0개·쿼리 0건을 확인했다.
원격 스키마·시험 데이터는 아직 넣지 않았으며 운영 D1은 생성하지 않았다.
시험 Worker·Google callback·배포 자격증명은 아직 준비되지 않았다.

구현된 화면을 기존 Pages에 먼저 배포하면 아직 없는 동일 출처 API를
호출하게 되므로 **현재 변경을 main에 즉시 push하면 안 된다.**
격리 시험 및 전환 절차를 거쳐야 한다.

## 실제 브라우저 점검

공개 산출물 디렉터리만 제공하는 loopback 시험 서버를 사용했다.
원본 저장소·비밀 설정·운영 API는 제공하지 않았다.

- 계정 화면: 로그인 안내와 신규 가입/기존 데이터 미이관 안내 표시.
- 관리자 화면: 로그인 전 관리 화면 접근 차단 및 연결 오류 안내 표시.
- 기업 상세 `?code=005930`: 기존 기업 기본 정보·배당·실적 표시.
  정적 태그 `대형주 반도체 즐겨찾기`가 사용자 태그 API 실패와 무관하게 유지됨.
- 이 시험 서버에는 API가 없으므로 API 오류 안내를 확인한 것이다.
  실제 Google 로그인·회원 가입 성공을 확인한 결과로 해석하지 않는다.

이후 실제 Worker 코드·정적 자산·메모리 내 가상 D1을 연결한 두 번째
loopback 시험에서도 확인했다. 계정 화면은 API 연결 오류 없이 익명 상태를
표시했고 기업 상세는 정적 태그와 빈 사용자 태그 목록을 정상 표시했다.
두 번째 시험 역시 실제 Google 요청은 차단했고 운영 계정을 사용하지 않았다.
시험 후 로컬 서버와 시험 탭을 종료했다.

### 인증 및 안전 기본값

로그인 활성화와 게시판 점검 모드는 분리한다. 운영에서 로그인을 활성화하면
관리자 준비 과정에서도 신규 회원이 생성될 수 있다. **첫 신규 회원 생성부터
새 데이터 보존이 필요한 복구 단계**로 취급한다. 게시판 점검 모드가 켜져
있다는 이유로 Supabase 단순 복귀가 안전하다고 판단하지 않는다.

토큰 검증은 가상 RSA 서명으로 정상 토큰 및 잘못된 서명·nonce·대상·발급자·
만료를 시험한다. 실제 Google 계정이나 운영 비밀 설정을 사용한 시험이 아니다.

## 최종 로컬 검증

- 잠금 파일 기반 의존성 재설치 성공. 설치된 의존성 감사 경고 0개.
  Windows의 시험 프로세스 파일 잠금 문제는 해당 시험 프로세스만 종료한 뒤
  재설치해 해결했다. 사용자 프로세스를 일괄 종료하지 않았다.
- TypeScript 타입 검사 통과.
- API 테스트 7개 시나리오 통과: 신규 스키마·권한·댓글·태그·제한,
  OAuth 정상/공격 토큰·동일 계정 재확인·독립 보안 회귀·코드 복구 등.
- 배포/자산/프런트엔드/상태/기존 레이아웃 등 Node 테스트 7개 묶음 통과.
- 최종 정적 빌드 성공, 공개 JSON 전체 해시 일치.
- 산출물 HTML·JS의 Supabase 문자열 및 SDK 호출 흔적 없음.
- 실제 Worker 버전 ID·스키마·Git SHA·manifest 검증 결과를
  `cloudflare/dist/verified-release.json` 및 Actions artifact에 기록하도록 구현.
  외부 배포가 없으므로 실제 운영 버전 기록을 생성한 것은 아니다.
- 동일한 가상 D1을 유지하며 코드 설정 A → B → A로 재기동한 뒤
  회원·댓글 읽기 및 새 쓰기 보존 확인. 실제 Cloudflare 버전 복구 시험은 아님.
- 변경 공백 검사 통과. companysearch 개발자·독립 검증 worktree와
  로컬 시험 서버 정리 완료. 원격 push 없음.

## 남은 작업 — 전체 마이그레이션 완료 아님

1. 시험 배포용 Cloudflare 접근 권한과 GitHub 시험 환경의 비밀 설정 연결.
   토큰은 채팅·Git·공개 산출물에 넣지 않는다. DNS·결제 권한은 시험 배포에 불필요하다.
2. 빈 시험 D1에 새 스키마 적용, 시험 Worker 배포 및 공개 SHA·해시 검증.
3. Google callback·동의 화면 설정, 사용자 직접 일반 로그인 검증.
4. **자동 월 비용 산정·예측은 미구현.** 현재 상태 점검기는 운영자가 입력한
   예상 비용의 7/9달러 수준만 검사한다. 값이 없으면 unavailable로 표시한다.
   실제 비용 수집·임계치별 중복 방지·GitHub 알림 수신 시험은 남아 있다.
5. 유료 운영 승인 여부·전환 시간 확인, 빈 운영 DB·Worker 설정,
   기존 서비스 쓰기 차단·DNS/캐시 전환·사용자 직접 관리자 지정.
6. 예약 작업의 전환된 공개 검증, 실제 Cloudflare 코드 복구 시험,
   오류 알림 수신, 7일 관찰 및 기존 서비스 정리 여부 확인.
