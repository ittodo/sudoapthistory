# Cloudflare 이전 — 기존 데이터 없이 새로 시작

기준일: 2026-09-13 (KST)

상태: 핵심 로컬 구현·검증 완료, 무료 시험 D1 생성. 운영 배포·DNS 전환·유료 가입·기존 서비스 종료 미실행.
이 문서는 과거 데이터 이관을 포함했던 계획을 대체한다.
실제 완료 내역과 미완료 항목은 [구현·검증 기록](cloudflare-implementation-status.md)을 참조한다.

## 확정 범위

사이트·게시판·로그인·기업 태그 기능을 Cloudflare로 이전한다.
**기존 Supabase 회원·댓글·닉네임·추천·사용자 태그·투표는 가져오지 않는다.**
**데이터 이관·회원 매핑·정방향/역방향 이관 도구는 범위에서 제외한다.**
빈 DB에 테이블을 만드는 스키마 마이그레이션만 구현에 포함된다.

| 영역 | 구성 |
| --- | --- |
| 정적 사이트 | Workers Static Assets, 기존 화면·URL·공개 JSON 유지 |
| 로그인·게시판·태그 API | Workers |
| 새 회원·댓글·추천·태그·투표 | 운영·시험 각각 분리한 D1 |
| 소스·배포 | 기존 GitHub 저장소 + GitHub Actions |
| 기업·부동산 수집 | 현재 PC의 companysearch·15_26 유지 |

R2와 별도 서버는 도입하지 않는다. 공개 기업·부동산 JSON, 정적 기업 태그,
수집 원본 DB, 수집 일정과 아침 브리핑 내용은 유지한다.
기존 사용자는 최초 로그인 시 신규 가입하며 기존 게시물·닉네임은 표시되지 않는다.
기존 Supabase는 전환 후 7일 보존하고 이후 사용자 확인을 받아 종료 여부를 결정한다.

## 정적 배포

- 공개 파일 허용 목록으로 산출물을 만든다. 문서·SQL·DB·로그·비밀 설정·
  소스·테스트를 제외하고 파일 개수·크기·금지 경로를 배포 전에 검사한다.
- 정적 파일은 직접 제공하며 `/api/*`, `/auth/*`만 Worker에서 처리한다.
- 없는 JSON은 404이며 HTML fallback으로 응답하지 않는다.
- HTML·버전 없는 JSON은 재검증하고 내용 해시 파일만 장기 캐시한다.
- 배포 버전으로 데이터 요청을 구분해 기존 브라우저 캐시를 우회한다.
- 전환 시 기존 `/data/` 강제 장기 캐시를 해제한다. 기존 규칙에는 호스트
  조건이 없었으므로 `app`에 영향이 없는지도 확인한다.
- `nodostream.com`이 주 도메인이고 `www`는 주 도메인으로 리디렉션한다.
  `app.nodostream.com`, 등록 기관, 관련 DNS·검증 레코드는 유지한다.

## 새 DB·인증·권한

운영 DB는 빈 상태로 시작한다. 시험 데이터는 운영 DB에 넣지 않는다.
회원·Google 계정 연결·세션·프로필·댓글·답글·댓글 추천·기업 태그·종목 연결·
태그 투표를 모델링한다. 기존 DB 정책·함수는 기능 참고 자료로만 사용한다.

- 기존 Google 프로젝트를 유지하고 새 callback을 추가한다.
  Supabase Auth는 새 서비스에서 사용하지 않는다.
- Google `sub`를 식별자로 사용하고 최초 로그인 시 새 내부 회원 ID를 발급한다.
- `oauth4webapi`로 PKCE·state·nonce와 토큰 서명·클레임을 검증한다.
- 세션은 HttpOnly·Secure·SameSite=Lax 쿠키이며 유효기간은 7일이다.
  DB에는 토큰 해시만 저장한다.
- 사용자 ID·역할은 서버 세션에서 결정한다. 본인 글 변경·관리자 권한·
  쓰기 요청 출처를 서버에서 검증한다.
- 최초 관리자는 사용자가 직접 로그인한 Google 식별자를 확인한 뒤
  운영 관리 명령으로 지정한다. 첫 가입자 자동 승격은 금지한다.
- Google 홈페이지·개인정보처리방침·승인 도메인·일반 사용자 로그인을
  검증한다. 기존 callback은 검증 기간에 유지한다.

| API | 기능 |
| --- | --- |
| `/auth/*` | Google 로그인 시작·완료 |
| `/api/session`, `/api/logout` | 상태·로그아웃 |
| `/api/profile`, `/api/account` | 닉네임·탈퇴 |
| `/api/comments` | 댓글·답글 조회·작성·수정·삭제 |
| `/api/comments/:id/like` | 추천 설정·취소 |
| `/api/stocks/:ticker/tags` | 태그 조회·추가 |
| `/api/tags/:id/vote` | 추천·비추천·취소 |
| `/api/admin/*` | 관리·통계·숨김·복원 |

- 댓글 최대 1,000자, 목록 기본 20개·최대 100개.
- 삭제·탈퇴 처리된 최상위 댓글에 공개 가능한 답글이 남아 있으면
  작성자 정보와 본문 대신 “삭제된 댓글입니다.” 안내를 표시하고 답글은 계속 공개한다.
  남은 공개 답글이 없으면 부모 자리도 숨긴다. 삭제된 부모에는 추천·새 답글·수정을 허용하지 않는다.
  관리자 숨김은 이 정책과 구분하며 해당 대화 전체를 계속 숨긴다.
  다른 회원의 답글은 연쇄 삭제하지 않는다.
- 탈퇴 시 계정·세션·프로필·본인 댓글 내용·투표를 삭제한다.
  다른 회원 답글과 작성자 없는 공유 태그는 보존하고 추천 집계도 갱신한다.
- 태그 생성·종목 연결·첫 추천은 원자적으로 처리한다.
- 추천·투표는 원하는 상태를 지정해 재시도가 상태를 반전시키지 않는다.
- 외부 Supabase 태그 자동 작성자가 발견되면 새 API로 연결한다.
  기존 사용자 태그 데이터는 가져오지 않는다.

## 실행 순서와 승인 지점

1. 사이트·자동 작업의 Supabase 의존성을 확인한다. 기존 데이터 건수 조사,
   회원 매핑, 이관 리허설은 제외한다.
2. 격리 환경에서 새 스키마·로그인·API·프런트엔드를 구현하고 가상 데이터로
   기능·보안·삭제 보존·재시도·제한·캐시 테스트를 수행한다.
3. GitHub Actions의 검증 → Cloudflare 배포 → 공개 확인을 구현한다.
   Git SHA·자산 manifest·Worker 버전·스키마 버전을 기록한다.
   준비 중에는 현재 Pages 배포를 유지하고 Cloudflare는 명시적 시험 실행만 허용한다.
4. 생성기 배포 검증을 명시적 공급자 설정에 따라 새 결과로 전환한다.
   동일 SHA·공개 파일 해시·공통 배포 잠금은 유지한다.
   수집 일정과 아침 브리핑 내용은 변경하지 않는다.
5. 빈 운영 D1·Worker, Google callback·비밀 설정을 준비한다.
   사용자에게 재가입과 기존 게시물 미표시를 안내한다.
6. **사용자와 전환 시간을 정한 뒤** 기존 서비스 쓰기를 차단하고 도메인을
   연결한다. 사전 구현 중 운영 쓰기를 막지 않는다.
7. 사용자 직접 로그인 → 식별자 확인 → 관리자 지정 → 일반 사용자·게시판·
   태그 점검 후 운영한다.
8. 전환 후 7일간 새 데이터·로그인·예약 배포·비용·오류를 관찰하고
   사용자 확인을 받아 기존 Supabase·GitHub Pages 종료 여부를 결정한다.

## 복구·비용·알림

- 신규 쓰기 전에는 기존 사이트로 복귀할 수 있다.
- 신규 회원·글·투표 발생 후에는 **D1을 유지하며 호환되는 이전 Worker로 복구**한다.
  Supabase 단순 복귀, 역이관, 새 데이터 폐기는 별도 결정 없이 실행하지 않는다.
- 중대한 장애에는 게시판을 점검 모드로 전환하고 정적 사이트는 계속 제공한다.
- 별도 수동 백업 파일을 만들지 않는다. D1 기본 복구 기능은 유지하며
  데이터 되감기는 자동 실행하지 않는다. Git은 코드 복구 수단이지 운영 DB 백업이 아니다.
- 기존 Supabase 7일 보존은 새 D1 데이터의 백업을 의미하지 않는다.
- 무료 시험 환경부터 시작한다. **운영 유료 가입은 별도 승인**이 필요하다.
  목표 예산 월 10달러는 과금 차단 한도가 아니다.
- CPU 목표 상한 50ms. 무료 환경에서는 실제 무료 플랜의 더 낮은 한도를
  따르며 상한 확보를 위해 자동 유료 가입하지 않는다.
- 요청 본문 16KiB, 조회 최대 100개, 사용자 쓰기 분당 30회,
  태그 제안 하루 20회 제한을 적용한다.
- API·인증은 캐시하지 않고 토큰·이메일·게시물 본문은 로그에 남기지 않는다.
- 배포 실패·서비스 이상·예상 비용 7달러/9달러 도달을 GitHub 알림으로
  전달하고 수신 시험한다. 예상 비용은 실제 청구액과 구분한다.
- 알림으로 자동 유료 전환하거나 서비스를 중단하지 않는다.

## 완료 확인표

- [ ] 기존 데이터 복사 없이 신규 가입부터 정상 동작
- [ ] 댓글·답글·추천·관리자·탈퇴·태그 기능 및 권한 테스트 통과
- [ ] 공개 JSON·정적 기업 태그·기존 URL 유지
- [ ] 새 서비스와 전환된 자동 작업에서 Supabase 의존성 제거
- [ ] 배포 산출물·파일 제한·캐시·JSON 404 검증
- [ ] 기업·부동산 예약 배포가 Cloudflare 공개 해시 검증까지 통과
- [ ] 일반 사용자 로그인 및 사용자 직접 관리자 지정 확인
- [ ] 새 데이터를 유지한 호환 Worker 복구 시험 통과
- [ ] GitHub 실패·상태·비용 알림 실제 수신 시험 통과
- [ ] 사용자 확인 시간에 도메인 전환 및 초기 운영 검증
- [ ] 7일 관찰 후 기존 서비스 정리 여부 사용자 확인

로컬 테스트, 실제 시험 환경 검증, 운영 검증을 각각 구분해 기록한다.
구현 완료만으로 외부 설정·로그인·전환·관찰 완료를 주장하지 않는다.
