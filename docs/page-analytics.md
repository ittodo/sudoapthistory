# 페이지 이용 통계

운영센터 `/admin/?view=pages`에서 오늘·최근 7일·30일의 페이지 조회수를 확인한다. 기본 기간은 7일, 날짜는 한국 시간이며 오늘을 포함한다. 단지 상세 패널도 페이지 조회에 포함한다. 페이지 로드·새로고침·뒤로 가기 복원마다 집계하고, 같은 문서의 검색 조건·탭 변경은 집계하지 않는다. 기존 단지 이용 통계는 별도로 유지한다.

`POST /api/analytics/pageviews`는 `{path,eventId,sentAt}`을 받는다. path는 허용된 정적 페이지 경로, eventId는 매 조회마다 생성한 UUID v4, sentAt은 Unix 초 단위 전송 시각이다. 동일 출처만 허용한다. 쿠키·방문자 ID·쿼리 문자열·IP는 통계 데이터에 저장하지 않는다. 같은 이벤트는 재전송해도 한 번만 집계한다. 전송 시각은 과거 24시간/미래 5분 범위에서 허용하며, 집계 날짜는 서버 수신 시각 기준이다. 중복 방지 ID는 2일 후 정기 작업에서 삭제하고 일별 합계는 유지한다. 자동화 요청까지 완벽히 구분하는 방문자 측정치는 아니다.

`GET /api/admin/page-analytics?days=7`은 운영자에게 `{days,from,to,total,data:[{path,name,views}]}`를 반환한다. 허용 기간은 1·7·30일이다. 기록이 없는 기간은 빈 배열과 합계 0을 반환한다. 새 페이지를 추가할 때는 서버 pages 목록과 HTML의 공통 스크립트를 함께 추가한다.

## 배포 순서

1. `npm run typecheck`, `npm run test:api`, `npm run test:site`, `node --test tools/test-cloudflare-page-analytics.mjs`, `npm run build`를 실행한다.
2. 스테이징 D1에 `0006_page_analytics.sql`까지 마이그레이션한 뒤 Worker와 정적 파일을 함께 배포한다. 기존 staging workflow는 이 순서로 실행한다.
3. 스테이징에서 익명 지도 진입·새로고침·단지 패널을 열고 운영자 통계에서 합계를 확인한다. 모바일 메뉴, 빈 기간, 조회 오류 재시도도 확인한다.
4. 운영 배포 workflow는 검토된 0006 SQL의 해시·운영 DB 대상·기존 마이그레이션을 확인한 뒤 새 집계 테이블과 인덱스만 추가한다. 적용이 확인된 후 Worker와 정적 파일을 함께 배포한다. 롤백 시 추가 테이블은 남겨 둔다.

이전 조회수는 소급 생성하지 않는다. 수집 스크립트 차단 또는 네트워크 실패 시 누락될 수 있다.
